# 论文起草（paper-drafting）

大纲与正文由**你自己**起草（你就是写作模型），srw_paper 工具只负责落盘、编译与门。
档位决定完备度——不要用 D1 的篇幅写 D3 的论文，也不要给快报硬凑 12 页。

## 工作流

1. **对齐刊物与档位**：`srw_paper {action:'state'}` 看当前 venue 与 tier；没应用刊物就先问用户选哪个（`venue.list`），不要替用户拍板。
2. **大纲**：`outline.prompt` 拿分档提示词 → 按其要求拟大纲（每节 title/intent/targetWords）→ `outline.save` → **把大纲完整展示给用户并等待确认**。用户没点头之前绝不调 `outline.confirm`（G1 门是用户的决定，不是你的）。
3. **正文**：确认后逐节起草。每节按 outline 里的 intent 与 targetWords 写**完整 LaTeX**，`section.write` 落盘（sectionId 用大纲节 id）：
   - 每节写完向用户报一句进度（已写 N/M 节）。
   - 数字、实验结果必须有来源：文献库真实条目（`\cite` 用库内 key）或实验产物；没有就写占位并显式标注 `[TODO: 待实验数据]`——**禁止编造**。
4. **编译**：全部节写完 `compile`；有错就按 errors[].file/line 修（错误在哪个节就改哪个节），修完重编；成功会自动留快照。
5. **引用**：`cite.audit` 查差集；缺的 key 若在文献库里 `refs.append` 一键补，不在就告诉用户先入库——不手写来源不明的 BibTeX。

## 档位纪律（D1/D2/D3）

- D1：4–6 页；1 数据集 × 2 基线；2–3 图 1 表；20–30 条引用；Related Work 可略。
- D2：8–10 页；2–3 数据集 × 4–6 基线 + 消融；5–8 图 3–5 表；40–60 条引用；必备数据/代码可得性与局限性声明。
- D3：12–20 页；3+ 数据集 × 6+ 基线 × 多种子 + 显著性 + 成本；8–15 图 5–10 表；60–120 条引用；+利益冲突/伦理/作者贡献。
- 写之前用 `compliance` 动作核对当前档位的检查项；写完再跑一次并汇报差距。

## 红线

- 大纲未确认（G1 未过）不得 section.write——工具会拒绝，不要绕。
- 引用 key 必须真实存在于文献库或 refs.bib；审计出的 missing 不能靠猜补。
- 编译失败最多自主修 3 轮，仍失败就把错误原样报给用户。
