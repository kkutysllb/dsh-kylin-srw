## 0. 一页纸结论

1. **「查论文」不是「能检索到 15 条 arXiv」**。以用户最终目的验收，它至少包含：把主题变成**可复现的检索集合** → 去重/撤稿核查 → **筛选排队** → **拿到可核验全文** → 引文扩充 → **批量精读** → **笔记/主题矩阵/综述骨架** → **可引用导出（BibTeX/Zotero）**。现状只完成了第一段的元数据部分与逐篇精读的单体。
2. **现状能力**：三源检索（单源、单次、≤50 条）→ 手工逐条入库 → 去重（有 year 漂移缺陷）→ arXiv PDF → 逐篇精读/译注版。**没有**检索计划、没有筛选打分与复核队列、没有引文网络、没有批量编排、没有笔记/矩阵、非 arXiv 全文取不到、DOI 校验不可达。
3. **12 项子能力评分：3 项「部分实现」/ 4 项「已实现但坏（含 1 项弱）」/ 5 项「根本没做」**（§1）。这与「M2 文献通路 ✅ / M3 订阅 ✅ / M4 精读 ✅」不矛盾：里程碑完成的是**通路与单体**，用户目的要求的是**综述级工作流**。
4. **基线本域 5 条 P0/P1 全部复现**（RateGate 8ms、OpenAlex 摘要空、title 键 year 漂移、非 arXiv OA PDF 全挡、DOI/撤稿死 API）；**另发现**基线把 M2 标 ✅ 但 0203 验收 #6 至今不可达（§3.1 第 1 条）、0203「白名单 config 可扩」无实现（§3.1 第 3 条）、0102 承诺的 tags/评分与 `notes/<citekey>.md` 未落地（§3.1 第 4 条）。基线无硬错误，但「完成度」与「验收可达性」两处口径需收紧。
5. **补全估算**：P0 止血 **9–13.5 人日**；做到「能支撑一次真实综述」再加 P1 关键项 **18–25 人日**；完整（含 Zotero 文件互操作、PRISMA、UI 拆分、性能）**34–46 人日**（§6）。
6. **完成判据不是功能清单，而是 12 条可执行断言 + 3 个真实场景**（§5/§8）：同一计划可重放、撤稿硬阻断、100 篇批量可断点续跑、矩阵每格可回链到 `paper.md` 块、非 arXiv OA 可下载、离线可重放。

### 2.2 逐项结论（区分「已实现但坏」与「根本没做」）

1. **非 arXiv OA PDF 失败——已实现但坏（产品缺口，安全侧是对的）**。白名单 5 域 + 跨源重定向拒绝，使 OpenAlex `best_oa_location.pdf_url` 指向出版商域时必然 `SSRF_BLOCKED`；Crossref 本身不产 pdfUrl/oaUrl（[crossref.ts:60](src/literature/crossref.ts#L60) 注释）。后果：库里除 arXiv 外的条目「取 PDF」按钮基本等于失败；错误文案只有 `SSRF_BLOCKED: 域名不在白名单`，用户无法自行解决。
2. **OpenAlex 摘要恒空——已实现但坏，但修好也不是「全有」**。`parseOpenAlexResults` 读不存在的 `abstract` 字段（P4）；即使改读 `abstract_inverted_index`（按 position 还原），外部探针显示该字段可为 `null`（nature12373）。因此验收应写成「结构上不再恒空 + 有覆盖率指标」，而不是「每条都有摘要」；同时可把 Crossref `abstract`/arXiv summary 作为回退。
3. **title 键 year 漂移——已实现但坏（数据正确性）**。键包含 year（[identity.ts:29](src/literature/identity.ts#L29)），自愈按同一键反查（[library.ts:163](src/literature/library.ts#L163)）；先入 `year:0` 再入 `year:2025` 永久两条（P1）。影响：库重复、citekey 退化、精读重复、综述计数错误。
4. **RateGate——已实现但坏（安全/礼貌风险）**。`loadLedger` 命中内存缓存就直接返回（[rate-gate.ts:84](src/literature/rate-gate.ts#L84-L98)），`mutate` 持锁也只读缓存（[rate-gate.ts:107](src/literature/rate-gate.ts#L107-L114)）；两实例交替 acquire 实测只隔 8ms（P2），换根后新根继承旧账本等待（P3）。对 arXiv 3s 礼貌间隔是真实封禁风险。
5. **检索「只有元数据」——检索层可用，但全文/引文网络根本没做**。三源返回 `LitCandidate`（标题/作者/venue/摘要/PDF 链接/被引数），没有全文块、没有 `references`、没有 `cited_by` 列表、没有 `openalexId`。这决定后续筛选、雪球、综述都没有原料。
6. **综述矩阵缺失——根本没做**。全仓无 matrix/review/screening 代码（grep 命中仅 `reading/recommend.ts` 的 G2 推荐，且未接线）。`reading/notes.ts` 生成的是**单篇**导读/节备注，不是跨论文主题矩阵。
7. **成本与 token**：检索便宜（1 请求/页）；但（a）`watch` 每个 tick 唤醒 1 个 agent turn（[model.ts:86](src/watch/model.ts#L86-L93)），15 分钟地板下单订阅一天最多 96 turn；（b）精读翻译是成本大头，`budget.ts` 预估纯函数存在但**未接线**（无参数/无确认门）；（c）2026 起 OpenAlex 有预算/计费与 key 要求，引文雪球会放大请求数。当前没有「先 triage 再深读」的成本闸。
8. **离线行为——部分实现，语义有坑**。`offlineMode` 让 search/pdf/watch 抛 `OFFLINE`，但 import/lib/bibtex/reading 可用；由于**没有检索结果快照**，离线时「查论文」退化为只能看已有库；错误文案让用户「在面板关闭离线模式」，但面板没有该开关（基线 P2）。
9. **撤稿/引用门——部分实现**。只有「新入库 60s 内且有 DOI」会被查；失败静默；`corrigendum` 只写 `notice` 不展示；撤稿只在 bibtex 内联跳过，`assertNotRetracted` 死代码；写作线 cite-audit 不读撤稿状态。用户「撤稿不能入库/引用」的预期未达成。
10. **UI 工作流——已实现但弱**。文献卡是「单源检索 → 单条入库 → 单条取 PDF」[workbench.tsx:1024](src/client/workbench.tsx#L1024-L1085)，无多选、无批量入库、无筛选、无错误解释；精读卡一次只处理一篇 [workbench.tsx:1103](src/client/workbench.tsx#L1103)。

**一句话**：当前「查论文」= 一个**元数据检索器 + 手工入库台 + arXiv 取文 + 单篇精读器**；缺的是把论文「查全、查准、读批量、写成综述」的那半条流水线。

## 4. 补全设计（可直接实施）

### 4.0 完成度阶梯（定义「补到什么程度算完成」）

| 级 | 含义 | 进入条件 |
|---|---|---|
| L0 现状 | 单次元数据检索 + 逐条入库 + arXiv 取文 + 单篇精读 | — |
| L1 可查全 | 检索计划三源并发、去重稳定、OA 全文可拿、可解释失败 | P0-1…P0-6 |
| L2 可复现 | 计划/运行/结果快照/重放/成本账；同一计划可解释差异 | P0-5 + C11 |

| L4 可持续 | 订阅增量、撤稿复查、预算闸、批量断点续跑 | P1-6 + P0-7 |

**「查论文」完成的定义 = 达到 L3，并对一个真实主题跑通 L4 的 4 周增量（§8）。**

### 4.3 检索计划 DSL、保存与复现

- **DSL**：每源一个子查询，编译到源语法；跨源统一归一后**本地排序**（`(year desc, citedBy desc, identityKey)`）以消除源排序差异；`filters` 只使用已实测字段（arXiv 用 `submittedDate`；OpenAlex 用 `from_publication_date/type/is_oa/cited_by_count`；Crossref 用 `from-pub-date/type`）。**未实测的字段必须先写探针再落 DSL**（外部资料见 §2.1）。
- **保存**：`searches/<planId>.json` + `fingerprint`；`plan.save` 不触网，`plan.run` 才触网；改名/改查询产生新 fingerprint。
- **运行**：`plan.run` 按「源 × 页」执行，单次调用设上限（建议 3 源 × 2 页或 60s），返回 `runId + counts + 是否 truncated`；大计划用 `plan.run.more` 续跑（**不引入 job 队列**，避免当前无 jobId 的架构改动；与 ADR-13 的长期目标分开）。
- **复现**：`plan.replay(runId)` 只读 `results.jsonl`，重跑去重/排序，断言 `resultHash` 不变；在线重跑写 `diff.json`，只允许「新增/删除」，不允许同键漂移。**「同一检索式两次一致」按两层定义**：离线重放必须逐字节一致；在线重跑必须「身份键集合无重复、排序确定、差异可解释」。
- **离线**：`plan.list/get/replay` 不触网，`plan.run` 抛 `OFFLINE`；这使「断网后还能整理论文」成立（当前不成立）。

### 4.4 引文网络（OpenAlex 优先，Crossref 兜底）

- **先补 id**：解析 OpenAlex 时保存 `openalexId`（`W…`）；对只有 DOI 的条目，用 `works/https://doi.org/<doi>` 单条补 id（单条查询外部计费极低，仍走预算账）。
- **后向（参考文献）**：OpenAlex `referenced_works`；Crossref `reference[].DOI` 兜底（外部探针确认存在）。
- **前向（被引）**：OpenAlex `filter=cites:<openalexId>`（外部探针可用；需分页与预算）。
- **相关**：OpenAlex `related_works` / `filter=related_to:<id>`（外部探针可用）。
- **雪球**：`citation.expand{planId, seedKeys, backward, forward, maxNodes}` BFS；新节点**只进 screening 队列，不直接入 library**（避免污染库）；边落 `citations/edges.jsonl`（`{from,to,kind,sourceId,runId,retrievedAt}`）；每轮记录请求数/成本；超限显式 `TRUNCATED`。
- **验收**：同一边不重复；深度/节点上限生效；每个新候选可回答「从哪个种子、哪条边来」。

### 4.5 筛选打分与人工复核队列

- **确定性打分（默认，零 token）**：
  - relevance：计划词/短语在 title（×2）与 abstract（×1）的加权覆盖，支持 must/exclude 词；
  - recency：`exp(-(currentYear-year)/5)`（注入时钟，禁硬编码）；
  - venue：venue 注册表 tier（复用 `src/venue`），未知 venue 给 0 不惩罚；
  - impact：`log1p(citedByCount)/10` 截断；
  - oa：可解析到 OA 全文记 1，否则 0（只作排序，不作准入）；
  - retracted：硬排除（不是降权）。
  分值四舍五入到 4 位并落盘，**同输入必同分**；每次打分记 `scoreHash`。
- **人工队列**：状态 `pending → include|exclude|maybe`；理由码（`off_topic / no_fulltext / not_peer_reviewed / duplicate / retracted / other`）+ 自由备注；变更只 append `log.jsonl`，投影 `queue.json` 带 revision CAS；支持「只看未决」「批量按分值段决策」「导入/导出 CSV」（为 PRISMA 留口）。
- **LLM 可选**：只做「建议 + 理由」，不直接改 include；prompt/模型/输入摘要哈希落盘；成本入预算账。**不做**「LLM 全自动决定纳入」。
- **UI**：文献卡新增「筛选」tab：表格（标题/年/venue/分值分解/状态/原因），键盘 j/k/a/e/m，批量入库只对 included。**落点**：拆出 `src/client/views/literature.tsx`（0201 M2 已规划），不要继续堆在 1,418 行单文件。

### 4.6 全文获取扩展（白名单 + 出版商 OA + 证据）

- **解析顺序**：arXiv `pdfUrl`（现有）→ OpenAlex `best_oa_location.pdf_url` / `open_access.oa_url`（现有字段，但被白名单挡）→ Unpaywall `best_oa_location.url_for_pdf`（需真实邮箱；用 `politeMailto`）。
- **主机策略（保持 SSRF 收紧）**：
  1. 静态白名单（现有 5 域 + `api.unpaywall.org`）；
  2. **解析器返回的出版商/仓储域**进入「待确认」：首次遇到写入 `fulltext.pendingHosts`，用户确认后进 `confirmedHosts[]`（落 `.srw/root.json`）；未确认 → `HOST_NOT_ALLOWED` 并给出可操作文案（「该 PDF 在 www.pnas.org，是否允许此域？」）；
  3. 仍只允许 https、钉死已校验 IP、逐跳重验；**跨 host 重定向仍拒绝**（需要时把目标 host 先确认）。
- **内容门**：`content-type` 含 `application/pdf` 或首 5 字节 `%PDF-`；否则 `CONTENT_NOT_PDF` 并删残件（当前无门，200 HTML 会落盘成 .pdf）。
- **证据**：`fulltext/<keySlug>.json` 记录每次尝试（`candidateUrl/resolver/host/httpStatus/finalUrl/sha256/bytes/contentType/license/at`）；`library.json` 的 `pdf` 追加 `url/finalUrl/retrievedAt/contentType`。**这是「补数据」与「专利在先技术」将来复用同一证据模型的接口。**
- **错误分类**：`NO_OA`（无 OA 位置）、`PAYWALLED`（解析到但非 OA）、`HOST_NOT_ALLOWED`、`CONTENT_NOT_PDF`、`RATE_LIMITED`、`NETWORK`。UI 逐条可解释，不再只显示 `SSRF_BLOCKED`。
- **红线**：不携带 cookie/机构凭据、不绕付费墙、不抓 Google Scholar；只取 `is_oa`/`license` 允许的副本。
- **RateGate**：为 `api.unpaywall.org` 等新域补间隔；**修 P0-2 后才允许扩域**（否则多域并发会绕过节流）。

### 4.7 批量精读编排（100 篇可断点续跑）

- **队列**：`reading/queue.json`，条目 `{key, paperKey, stage: extract|translate|notes|export|done|failed, attempts, lastError, updatedAt}`；只允许 `has-pdf` 条目入队；stage 只前进。
- **执行模型（沿用引擎车道，不新建 job 系统）**：
  1. host 批量 `extract`（零 LLM，可一次多篇；单篇失败只标 failed）；
  2. 对每篇 `status` 取 `pendingIds` → agent 按 ≤40/批 `translate` → 服务端 clamp；
  3. 全部译完 → `notes`（逐节）→ `export`；
  4. `queue.next` 返回「下一批」（建议 1 篇 + ≤40 块），agent 逐批汇报进度；`queue.resume` 从任意断点继续。
- **必须先修的续跑前提（P0-7）**：`service.translate` 先落已成功缓存再抛错（当前 [service.ts:285](src/reading/service.ts#L285-L287) 先抛后写）；`finish='length'` 视为失败；`keys` 服务端 ≤40；`timeoutOf` 已 abort 快速失败（否则取消/测试拖 60s）。
- **成本门**：入队时 `budget.estimate`（现成纯函数）→ 预估 token/费用；超阈值需用户确认；每批记 `usage`；队列级 `maxConsecutiveFailures`（默认 3）自动暂停。
- **并发**：默认 1 篇/1 批，避免与 RateGate、LLM 限流打架；可配 2。
- **验收**：假 LLM 计数；100 篇跑到第 50 篇 kill → resume 后「已完成块 0 次 LLM 调用」，总调用数 = 唯一块数。

### 4.8 笔记、主题矩阵与综述骨架

- **笔记**：`literature/notes/<keySlug>.md`，frontmatter `key/paperKey/tags/claims[]/createdAt`；正文每条断言必须带证据引用：
  ```text
  - claim: 该文在 X 数据集上报告 Y
    evidence: <!-- srw-ref paperKey=doi-10-… block=p5-b2 hash=… -->
  ```
  校验器：`paperKey` 存在、`blockId` 在 `source_map` 中、`srcHash` 与当期块一致；断链 → 渲染失败而不是静默。
- **主题矩阵**：`rows` = included 论文，`cols` = 主题（从 tags 聚合 + 手工增删）；每格 `statement + evidence[] + confidence + status`；**空格显示 TODO，不自动编造**；渲染 `matrix.md` 时每格附 `[p5-b2](../reading/<paperKey>/paper.md)` 链接与「回到块」入口（面板用 `reading.content` 滚动定位）。
- **综述骨架**：`protocol.json`（问题、范围、纳入/排除标准、检索计划、PRISMA 计数）→ `matrix.md` → `outline.md`（章节树，可一键转成 `paper/outline.json` 的 draft，**仍走 G1 用户确认门**）→ `gaps.md`（空格/冲突/证据不足清单）。
- **与写作线接口**：`outline.md` 的每节带 `citekeys[]`；经 `writer.outline.save` 落盘后，`section.write` 只允许引用已 included 且未撤稿的 key（cite-audit 增一条硬门）。
- **不做**：自动写整篇综述、无证据的「AI 总结」；矩阵单元格没有 evidence 指针时禁止 confirmed。

### 4.9 BibTeX / Zotero 互操作（遵守 0102 §2.2 冻结口径）

- **先修 BibTeX 质量**：类型映射用 `type` 而非 venue 关键词猜；`@article` 用 `journal`、`@inproceedings` 用 `booktitle`；补 `pages/volume/number/publisher/url/urldate`；arXiv 条目写 `eprint/archivePrefix/primaryClass`；作者保留 given+family（Crossref 现在只存 family）。
- **citekey**：保留现有确定性公式为 `policy='srw'`，新增 `policy='biblatex'`（`familyYear+shorttitle`）与 `custom`；映射写 `library.json` 的 `citekey`，避免每次导出漂移；冲突 `-2/-3` 保持。
- **导入**：`literature/imports/*.bib` + `refs.import`：手写解析器（括号配对、`@article{key,`、`field = {…}`/引号）→ `candidateFromInput`；来源标记新增 `'bibtex'`（`LitSource` 加一个成员；watch 的 source 枚举仍只允许三源）。
- **导出**：`exports/library.bib`（全库）与 `paper/refs.bib`（论文用）分离；导出前过撤稿硬门；导出清单 `exports/<ts>.manifest.json`（含 citekey 列表、sha256）。
- **Zotero**：**只做文件互操作**（Zotero 导出 .bib → 我们导入；我们导出 .bib → Zotero 导入），不做 API/daemon/数据库直连。0102:73 已冻结「Zotero 互操作交给生态，我们导出/导入 BibTeX 即可」；若用户要求实时同步，需先改 ADR，不在本轮偷偷扩。
- **验收**：同一库两次导出 citekey/内容一致；导入后再导出 round-trip 不丢 DOI/arXiv id/作者全名；撤稿条目永不出现。

| A9 | 筛选确定性 | 同输入跑两次 `screen.auto` | `scoreHash` 相同；log 追加；include 数 = 入精读队列数 |
| A10 | 离线可整理 | `offlineMode=true`：plan.get/replay、library、review、reading | 全部可用；search/pdf/watch/plan.run 抛 `OFFLINE`；fetch stub 0 次 |
| A11 | 成本门 | 队列预估超 `budget.maxTokens` | 返回 `CONFIRM_REQUIRED`；确认后才执行；`run.cost` 落盘 |
| A12 | 订阅增量 | 同一订阅 `run` 两次；加日期过滤后再 run | 第二次 fresh=0；第三次只新增窗口内；lastResult 更新；无重复键 |

测试组织建议：`tests/lit-plan.test.ts`、`lit-fulltext.test.ts`、`lit-screen.test.ts`、`lit-cite.test.ts`、`lit-refs.test.ts`、`reading-queue.test.ts`、`review-matrix.test.ts`；网络层继续用本地 `node:http` 靶机 + fixture，不连真网；真网只在里程碑收尾做「活体签字」。

### 6.4 先修哪几个才「真可用」

**顺序：P0-1 → P0-2 → P0-3 → P0-4 → P0-5 → P0-6 → P0-7 → P0-8**。其中：
- **P0-1 + P0-4** 决定「能不能拿到全文」（没有全文，精读/综述都是空转）；
- **P0-3** 决定「库是不是可信」（重复/丢 DOI 会污染后续所有统计与引用）；
- **P0-5** 决定「能不能复现」（用户明确要「查论文」，不可复现的检索不算查）；
- **P0-7** 是批量精读的**前置**，不修就会「100 篇一失败全丢」。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| OpenAlex 2026 计费/key/cursor 限制（外部资料，需实现前复验） | 大计划翻页失败/预算超支 | 配置 `openalex.apiKey`；无 key 明确 `TRUNCATED`；预算账；缓存 DOI→OpenAlexId |
| 出版商 OA 页面反爬/链接过期/不是 PDF | 全文失败率高 | 只走 Unpaywall/OA 官方位置；记录 attempt；失败给 `PAYWALLED`；不绕付费墙 |
| 动态允许出版商域削弱 SSRF | 内网/重绑定风险 | 域必须来自解析器 + 用户显式确认；仍钉 IP、https、逐跳重验、禁跨 host 重定向 |
| 「同一检索式一致」与真实 API 漂移冲突 | 验收误判 | 离线重放必须逐字节一致；在线只承诺「无重复 + 确定排序 + diff 可解释」 |
| 合并过猛（同题不同文） | 丢论文 | 弱键合并需作者/年/venue 至少一项重合；歧义标 `possibleDuplicateOf` 交人工 |
| 批量精读烧 token | 成本失控 | triage 先行 + 队列预估 + maxTokens 确认 + 失败熔断 + 只深读 included |
| `library.json` 单文件全量重写/并发 STALE | 大库慢/import 失败 | 批量 `updateMany`、读-改-重试、import ≤100/批；P2 再拆文件/索引 |
| 订阅每 tick 唤醒 agent | 隐性 LLM 成本 | 合并同项目到期订阅为一次 run；提高新订阅地板（如 6h）；文档显式标注「每 tick ≈1 turn」 |
| Zotero 实时同步越界 | 违反 0102 冻结口径 | 只做 .bib 文件互操作；如需同步先改 ADR |
| 笔记/矩阵无证据编造 | 学术诚信风险 | evidence 指针必填 + 校验器 + 空格 TODO；不确认无证据单元格 |

## 8. 什么算「查论文」完成（给 Lead 的验收口径）

1. **12 条断言（A1–A12）全绿**，且进入 `pnpm check` / 新 `test:gates`；P0 清单零 open。
2. **真实场景 S-A（综述闭环）**：选一个真实主题 → 三源计划（≥300 identified）→ 去重（≤5% 重复）→ 自动打分 + 人工筛选（include ≥40）→ 全文获取（≥80% included 拿到 PDF，其中非 arXiv ≥50%）→ 批量精读（≥20 篇）→ 矩阵（≥5 主题 × 20 行，每格有 evidence）→ 综述骨架（8 节）→ `refs.bib`（≥40 条，citekey 稳定、无撤稿）。
3. **S-B（增量）**：一条订阅连续 4 周（或压缩为 8 次 run）：0 重复入库、新条目可见、撤稿复查覆盖、每次 run 有 lastResult 与预算记录。
4. **S-C（离线/迁移）**：把项目目录拷到另一台机器，断网：`plan.replay` 结果一致、笔记/矩阵/精读可读、导出 refs.bib 成功；网络动作明确 `OFFLINE`。
5. **可解释性**：任一库条目能回答「来自哪个计划/哪次 run/哪次筛选决策/哪个全文 URL/哪次撤稿核查」；任一矩阵单元格能回跳到 `paper.md` 的具体块。

**明确不算完成**：能搜到 15 条 arXiv；能手工入库 100 条；能单篇精读；能导出 3 条 refs.bib。这些是 L0/L1 的局部，不是用户要的「查论文」。
