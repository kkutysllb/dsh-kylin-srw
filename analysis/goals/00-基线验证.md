## 3. P0 复核（全部成立）

### P0-1 TeX runner 从未装配 —— **成立（实测，强于基线）**

- 代码事实：`src/writer/run.ts:8` 定义 `nodeRun`，全仓库 `grep nodeRun src tests scripts` **只有定义、零引用**；`src/service.ts:116-124` 构造 `WriterService` 时只传 `fs/rootDir/libraryEntry`，无 `run`；`src/writer/service.ts:48` 的 `run?` 可选，`:254-259/270` 缺省走 `throwNoRunner`（`:408-410`）。
- 实测探针（`/tmp/srw-probe-p0-runner.mts`）：在临时 PATH 放一个可执行假 `tectonic`（输出 `tectonic 0.15.0-fake`）后：
  - 直接 `new WriterService({ run: nodeRun })` → `engine='tectonic'`、probe available=true；
  - `SrwService.open(...).writer.state()` → 四引擎 available 全 false、`engine=undefined`；`compile()` 抛 `ENGINE_MISSING`。
- 基线证据（lib 无 `child_process`）也复核为 0/0/0。
- **判定**：生产路径编译恒不可用，与「本机没装 TeX」无关；M5 核心承诺不可达。

### P0-2 RateGate 内存缓存破坏跨实例/换根 —— **成立（实测）**

- 代码事实：`src/literature/rate-gate.ts:84-98` `loadLedger()` 命中 `this.cache` 直接返回；`:107-114` `mutate` 全程持文件锁但读的是内存缓存；`:54-56` 注释声称 getter 支持换根，却没有按 path 失效。
- 实测探针（`/tmp/srw-probe-rate2.mts`，interval=10s，sleep 为 no-op 只验预约）：
  - 账本先写 `lastRequestAt=T+30,000`；实例 A 首次 `acquire` 装入缓存；外部把账本改写为 `T+60,000`；A 再 `acquire(T+1)` → 预约在 **T+51,751**，比外部预约早 **8,249ms**，并把账本从 `T+60,000` **回写为更早的 T+51,751**。
  - 换根：根 2 账本已有 `lastRequestAt=T+500,000`；同一 gate 切根后 `acquire` → 预约 **T+20,631**（早 479,369ms），并覆盖根 2 账本。
- **判定**：跨进程/换根的唯一性承诺失效；两个客户端可同时打同一域，存在被封禁风险。

### P0-3 main.tex 的 \input 与 outline 脱钩 —— **成立（实测，含两个子症状）**

## 5. 基线错误与修正（必须回写）

**B1（小错）pnpm 版本**：基线 §9.1 写「pnpm 11.7」，实测 `pnpm 11.23.0`；node 24.18.0 正确。

**B2（关键归因错误）61.7s 不是 timeoutOf 预取消造成**：
- 证据链（实测）：`tests/reading-translator.test.ts` **单文件 61.3s**；该文件内单条用例最长 830ms；只跑「外部取消及时中断」一条 → **60.14s**；只跑「超时不挂起」→ 165ms；全套加 `--test-force-exit` → **1.78s**（163 全过）。
- 代码事实：`src/reading/translator.ts:142-147` 外部取消用独立 Promise 与 `run` 竞速，`:200-205` 竞速失败后只挂 `catch`，**不终止仍在 `timeoutOf(60_000)` 里的 4 个 worker**；测试假 LLM `hang:true` 忽略 abort，于是 4 个 60s 定时器让事件循环多活 60s。
- 结论：`timeoutOf` 预取消问题真实存在（P1-16），但不是套件 61s 的原因；修复应是「取消时让 worker 的 timeout 定时器 `.unref()` 或显式 abort/清账 + 假 LLM 响应 abort + 测试加 `--test-force-exit`」。顺带建议把该用例 `timeoutMs` 改为 1–2s。

**B3（严重度修正）P1-17 不是死路**：scaffold→confirm 后虽 `sectionWrite` 报错，但再 `outlineSave` 会分配 `file` 并回到 draft，再 confirm 即可写。影响是流程摩擦 + 首轮误导，不是不可恢复。建议归 P2。

**B4（产物来源）build/main.pdf 是误提交的假文件**：`git log -- build/main.pdf` → 提交 `1dab90c`；内容 20 字节 `%PDF-1.4 fake output`，与 `tests/writer-service.test.ts:55` 假引擎字符串一致。`build/main.log` 未被跟踪（`.gitignore:*.log`），内容 `Output written on main.pdf (6 pages, 12345 bytes).` 与测试假日志 `:56` 一致。二者**都不是真实编译产物**；当前测试只写 mkdtemp，不再写仓库（验证期间 mtime 变化来自并发探针）。建议 `git rm --cached build/main.pdf` 并确认 `build/` 不入库。

**B5（命名陷阱）src/verify 不是 M6**：该目录只有 `retraction.ts`（M2 撤稿检查，文件头注明 0203 Task 2.9 / 0204 Task 3.6）。M6 的素材/证明链代码不存在；不要把目录名当里程碑进度。
