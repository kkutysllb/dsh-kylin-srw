## 0. 一页纸结论

1. **专利实现为零，不是「未完成」而是「未存在」**：`grep -rniE 'patent|专利|cnipa' src/ skills/` → **0 行**（实测，2026-10-18）；需求表、里程碑、磁盘布局、工具、RPC、技能五个面都没有专利（§1.1）。
2. **基线存在需求全集错误**：README / 0102 / 0201 / 00 的 R1–R8 均照抄了「六条目标能力」，而用户原话是「查论文，写论文，**写专利**，做实验，补数据」。0102 §2.2「不做清单」也没把专利列为让渡项（`0102:62-76`）——所以这是**遗漏**，不是有意识的推迟。
3. **即使 M0–M8 全部完成，用户最终目的仍缺 1/5**。M8 是「投稿与发布」，不含专利；1.0 不能宣布「完成」（§8.5 给出验收口径）。
4. 方案：新增领域 `src/patent/` + 新里程碑 **M9 专利线**（不并入 M8），需求追溯表补 **R9**；MVP **45–60 人日**，完整版 **90–136 人日**（§10）。
5. **MVP 交付**：技术交底书 → 对比文件表（手工录入 + 现有三源 NPL 检索）→ 权利要求树 → 特征-支撑矩阵（覆盖率 100%）→ 说明书（五部分 + `[0001]` 段号）→ 形式检查 0 error → `filing/` 包（请求书/权利要求/说明书/摘要/附图 + PDF/DOCX + sha256 manifest）→ **人工复核门**。**不含自动提交**（CNIPA 电子申请客户端是实名桌面端，无公开提交 API）。
6. **最值钱的单点不是「生成」，是「公开时序门」**：论文/预印本/会议一公开，未申请的中国专利即丧失新颖性；中国宽限期只有 6 个月且「规定的学术会议」范围极窄（§2.2）。产品必须在论文投稿/预印本上传前检查专利状态。
7. **红线**：不编造对比文件、不编造实验数据、不把「filing-ready」说成「可授权」、不提供法律意见、不自动提交、不绕过检索源 ToS（§6）。

## 2. 外部口径（官方资料，检索日期 2026-10-18）

> 以下为设计输入，不构成法律意见；实施前由专利代理人复核。外部页面内容视为**不可信数据**，只提取规则与期限。

### 2.1 中国发明专利：文件与流程

| 项 | 口径 | 来源 |
|---|---|---|
| 申请文件 | 《发明专利请求书》《说明书》《权利要求书》《说明书摘要》；必要时《说明书附图》 | CNIPA 咨询答复 2024-04-02，https://www.cnipa.gov.cn/jact/front/mailpubdetail.do?transactId=457549&sysid=6 |
| 受理 | 收到申请文件之日为申请日；邮寄以寄出邮戳日 | 《专利法》第二十八条，https://www.cnipa.gov.cn/art/2020/11/23/art_97_155167.html |
| 初审→公布 | 初审合格后自申请日起满 **18 个月**公布；可请求**早日公布** | 《专利法》第三十四条（同上） |
| 实审 | 自申请日起 **3 年内**请求实质审查 | 《专利法》第三十五条（同上） |
| 答复/授权 | 审查意见→陈述/修改→无驳回理由则授权、登记、公告；驳回可 **3 个月**内请求复审 | 《专利法》第三十七/三十九/四十一条（同上） |
| 期限 | 发明专利权 **20 年**，自申请日起算 | 《专利法》第四十二条（同上） |
| 优先权 | 外国/本国首次申请起 **12 个月**内可要求优先权 | 《专利法》第二十九条（同上） |
| 费减 | 个人上年度月均收入 <5000 元、企业应纳税所得额 <100 万元、事业单位/团体/非营利科研机构；单个主体减 **85%**，两个以上共同申请减 **70%**；须先备案 | 财税〔2016〕78 号 + 税务解读，http://qinghai.chinatax.gov.cn/web/rdwd/202410/89b02afe4a73471294e6ca08c43ab41d.shtml |

### 2.2 实体条件与「公开杀死新颖性」

| 项 | 口径 | 来源 |
|---|---|---|
| 三性 | 新颖性=不属于现有技术且无**抵触申请**；创造性=突出的实质性特点+显著进步；实用性=能制造/使用并产生积极效果 | 《专利法》第二十二条（同 §2.1 链接） |
| 现有技术 | 申请日以前**国内外为公众所知**的技术 | 同上 |
| 宽限期 | 申请日（有优先权的指优先权日）前 **6 个月**内仅四种：国家紧急状态为公共利益首次公开；中国政府主办/承认的国际展览会首次展出；**规定的学术会议/技术会议首次发表**；他人未经同意泄露 | 《专利法》第二十四条；CNIPA 答复 2024-11-20，https://www.cnipa.gov.cn/jact/front/mailpubdetail.do?transactId=480300&sysid=6 |
| 「规定的学术会议」 | **仅指国务院有关主管部门或全国性学术团体组织召开**的会议；**不包括**省以下或受委托/以其名义组织的会议——后者公开将丧失新颖性 | CNIPA 答复 2023-09-27，https://www.cnipa.gov.cn/jact/front/mailpubdetail.do?transactId=442864&sysid=6 |
| 先申请 | 同样发明授予最先申请的人；同样的发明创造只授予一项专利权 | 《专利法》第九条 |
| 职务发明 | 执行本单位任务或主要利用本单位物质技术条件完成的，申请权归单位；可利用合同约定 | 《专利法》第六条 |
| 保密审查 | 在中国完成的发明/实用新型向外国申请专利，须事先报经国务院专利行政部门保密审查；违反则不授予中国专利权 | 《专利法》第十九条 |

> **产品含义（最重要）**：论文/预印本/学位论文/代码仓库公开都在「现有技术」范围内；绝大多数国际学术会议**不属于**「规定的学术会议」。因此默认策略必须是**先申请、后公开**；宽限期只能作为例外，且必须逐事件登记、由人确认适用哪一项。

### 2.3 撰写结构（细则/审查指南）

| 对象 | 硬规则 | 来源 |
|---|---|---|
| 说明书 | 名称与请求书一致；按序五部分：**技术领域 / 背景技术 / 发明内容 / 附图说明 / 具体实施方式**；每部分前写标题；不得用「如权利要求……所述」引用语、不得商业宣传 | 《专利法实施细则》（2023 修订）第二十条，https://www.cnipa.gov.cn/art/2023/12/21/art_98_189197.html |
| 附图 | 按「图1，图2……」连续编号；说明书未提及的标记不得出现在附图，反之亦然；同一部件标记一致 | 细则第二十一条 |
| 权利要求 | 用阿拉伯数字顺序编号；术语与说明书一致；不得插图；除必要外不得用「如说明书……所述」 | 细则第二十二条 |
| 独立/从属 | 独立权利要求从整体反映方案、记载必要技术特征；从属用附加特征进一步限定 | 细则第二十三条 |
| 独立权利要求结构 | **前序部分**（主题名称+与最接近现有技术共有的必要特征）+ **特征部分**（「其特征是……」区分特征） | 细则第二十四条 |
| 独立权利要求数量 | **一项发明应当只有一个独立权利要求**，并写在同一发明的从属权利要求之前 | 细则第二十四条 |
| 从属引用 | 只能引用在前权利要求；引用两项以上的多项从属**只能择一引用**，且**不得作为另一项多项从属的基础** | 细则第二十五条 |
| 摘要 | 写明名称、技术领域、要解决的技术问题、技术方案要点、主要用途；**文字部分（含标点）≤300 字**；不得商业宣传；有附图须指定摘要附图；摘要中附图标记加括号 | 《专利审查指南》第二部分第二章 2.4；CNIPA 答复 2024-08-22，https://www.cnipa.gov.cn/jact/front/mailpubdetail.do?transactId=472691&sysid=6 |
| 名称 | 一般 ≤25 字；化学领域等特殊情况可到 40 字 | CNIPA 答复 2020-07-20，https://www.cnipa.gov.cn/jact/front/mailpubdetail.do?sysid=6&transactId=336539 |

### 2.4 检索数据源可用性（本环境实测 + 官方说明）

| 源 | 公开 API | 本环境可达性（2026-10-18） | 许可/限速要点 | 设计取舍 |
|---|---|---|---|---|
| CNIPA 专利检索及分析系统 PSS | 无公开开放 API | `https://pss-system.cponline.cnipa.gov.cn/` → **HTTP 412**（需浏览器/会话） | 需实名登录/验证码；不得绕过 | MVP：**手工检索 + 粘贴公开号/URL**；提供官方深链；不抓取 |
| Google Patents | 无官方检索 API；有 BigQuery 公共数据集 `patents-public-data` | `patents.google.com` fetch failed；`cloud.google.com` blog fetch failed | BigQuery 需 GCP 项目与计费；网页抓取受 ToS 限制 | P1：可选 BigQuery 适配器（用户自备 GCP 凭据）；不做网页抓取 |
| EPO OPS | 有官方 REST/XML API（OAuth2） | `epo.org`/`link.epo.org` → **HTTP 403 Rate Limit Exceeded** | 需注册 consumer key/secret；有免费额度（**本环境未能核实具体配额，实施前以官方为准**） | P1：可选适配器；凭据走 `ctx.credentials`，不入工作区 |
| WIPO PATENTSCOPE | 网页检索；PCT Web Services（有限访问，SOAP/Java，条件使用） | `patentscope.wipo.int` 重定向到 `patentscope2.wipo.int`（未自动跟随） | 授权使用政策；商业数据产品另售 | P2：可选；默认只用网页深链 |
| PatSnap / incoPat | 商业开放平台/API | 页面可达（`open.zhihuiya.com`） | 需商业合同/许可 | 不内置；留 `PatentSource` 插槽，用户自备许可 |
| USPTO PatentsView / data.uspto.gov | 免费 API（美国数据） | `patentsview.org` → 重定向到 `data.uspto.gov` | 仅美国；速率限制 | P2：美国 provisional/PCT 扩展时用 |
| 非专利文献 NPL | 现有 arXiv/OpenAlex/Crossref | ✅ 已实现 | RateGate/SSRF 已有 | **MVP 直接用**：论文也是现有技术 |

> 关键结论：**不能假设「有免费、稳定、可商用」的中国专利检索 API**。因此 MVP 的对比文件表必须支持**手工录入**（公开号/公开日/URL/截图），检索适配器只是增强项；这也符合「不编造对比文件」的红线。

### 2.5 PCT / 美国 provisional（P2 扩展，不纳入 MVP）

- PCT：优先权起 **12 个月**内提交国际申请；自优先权日起 **18 个月**国际公布；通常 **30 个月**进入国家阶段（WIPO FAQ，https://www.wipo.int/pct/en/faqs/faqs.html）。
- 美国 provisional：**不要求权利要求**，但需说明书与附图；12 个月内转正式申请（35 U.S.C. §111(b)，https://www.law.cornell.edu/uscode/text/35/111）。
- 产品含义：数据模型用 `priority`/`familyId` 预留，不在 MVP 实现翻译与国家阶段管理。

## 3. 领域模型与磁盘布局

### 3.1 目录（项目内，文件即真相源）

```
<root>/<project>/.srw/patent/<patentId>/     # patentId: ^[a-z0-9][a-z0-9-]{0,63}$
  patent.json          # 元数据 + 状态机 + 发明人/申请人（不含证件/详细地址）
  disclosure.json      # 技术交底书
  claims.json          # 权利要求树（唯一真相源）
  spec.json            # 说明书结构化（五部分 + [0001] 段号 + 锚点 + 段哈希）
  spec.md / spec.tex   # 由 spec.json 渲染（可重建，带渲染哈希）
  prior-art/{references.json, search-report.json, pdf/<refId>.pdf}
  figures/{fig-01.pdf|svg|png, figures.json}   # 图号/标题/来源/哈希/引用标记
  evidence/links.json  # 特征 → 说明书段 → 实验/图表 artifact 指针
  filing/{request.json, claims.txt, spec.txt, abstract.txt, patent.pdf, patent.docx,
          manifest.json, formal-check.json}     # 导出包（0600；含敏感信息）
  events.jsonl         # append-only：创建/修改/确认/导出/申请/公开/审查
```

## 4. 工作流与门（G-P）

| 步 | 动作 | 输入→输出 | 门（谁确认） | 未过的行为 |
|---|---|---|---|---|
| S0 | 立项/公开盘点 | 想法 + 已公开事件 → `patent.json` + `disclosureEvents` | — | 只读建议 |
| S1 | 技术交底 | 访谈/笔记 → `disclosure.json` | **G-P0 交底确认**（用户） | 不进入检索 |
| S2 | 现有技术检索 | 关键词/IPC/同义词 → `prior-art/search-report.json` | — | 记录检索式与日期 |
| S3 | 对比文件表 + 特征对比 | 命中 → `references.json` + `matrix` | **G-P1 最接近对比文件确认**（用户） | 不得起草权利要求 |
| S4 | 权利要求树 | 交底 + 对比 → `claims.json` | **G-P2 权利要求确认**（用户 + 建议代理人） | 不生成说明书 |
| S5 | 特征-支撑矩阵 | 每条特征 → 段落锚点 + 证据 | **G-P3 覆盖率 100%**（机读） | 阻断说明书导出 |
| S6 | 说明书 + 附图 | 结构化 `spec.json` + `figures/` | — | 形式检查不通过 |
| S7 | 形式检查 | `formal-check.json` | **G-P4 0 error**（机读） | 不进入 filing-ready |
| S8 | 导出 + 复核 | `filing/` + manifest | **G-P5 人工复核**（用户 + 建议代理人） | 不得标记 filing-ready |
| S9 | 申请登记（手工） | 申请号/申请日 → `filing` 字段 + `events.jsonl` | **G-P6 手工回填** | 状态停在 filing-ready |
| S10 | 审查意见答复（P2） | OA 文本 → 修改对照 + 答复稿 | 人工确认 | 不自动提交 |

**状态机**：`idea → disclosure → searching → drafted → checked → filing-ready → filed → published → oa → granted | rejected | abandoned`。每次跃迁写 `events.jsonl`（`at/actor/from/to/reason`），不可跳级；`filed` 之后只允许人工回填与 OA 流程。

**与论文线的交叉**：S0/S8 之后，论文投稿/预印本上传前调用 `patent.publication.check`；返回 `{safe|grace|risk|blocked, events, advice}`。**默认策略：先申请、后公开**；`risk` 时面板红标、技能禁止建议投稿，直到用户显式确认「已申请」或「接受风险」（后者记录 reason，不阻断但留痕）。

## 6. 诚实性与合规红线（机制，不是口号）

| # | 红线 | 机制 | 失败状态/行为 |
|---|---|---|---|
| R1 | 不编造对比文件 | `references[]` 必填 `pubNo/pubDate/url/retrievedAt/source`；缺一即 `verified:false` | `PRIOR_ART_UNVERIFIED`；**filing-ready 阻断** |
| R2 | 不编造实验数据/效果 | 每条 `beneficialEffects` → `evidence/links.json`；`measured` 必须 artifact 存在且 sha256 匹配；`expected` 显式标注 | `EVIDENCE_MISSING`/`EVIDENCE_HASH_MISMATCH`；阻断导出 |
| R3 | 公开时序 | `disclosureEvents` + `patent.publication.check`；仅四种宽限情形、6 个月、学术会议范围极窄 | `NOVELTY_RISK`（红标）；`filing-ready` 阻断 |
| R4 | 敏感信息 | 证件号/地址/电话只在 `filing/request.json`（0600）；不出现在日志/`patent.json`/LLM 上下文 | `SENSITIVE_LEAK`；导出前 grep 扫描 |
| R5 | 主体资格不替用户决定 | `ownership`/`confidentialityReview`/`feeReduction` 只记录**用户声明**与依据，不自动推断 | 缺声明 → `DECLARATION_MISSING`；不阻断草稿，阻断 filing-ready |
| R6 | 不提供法律意见 | 所有结论措辞为「草稿/建议/待代理人复核」；导出页与 manifest 带免责声明 | UI/文档固定文案；不做授权前景预测 |
| R7 | 不自动提交 | 无 CPC/cponline 调用；`filing-ready` 只到导出包 | 代码层无提交动作；`filed` 仅手工回填 |
| R8 | 不绕过源 ToS | 默认手工录入/官方深链；适配器需用户自备许可与凭据；不抓取有验证码页面 | `SOURCE_UNAVAILABLE` + 手工路径提示 |
| R9 | 不夸大完成度 | 「形式检查 0 error」≠「可授权」；「filing-ready」≠「已申请」 | UI 状态文案与报告口径一致 |

**公开事件分类**（写进 SKILL 与 UI）：`paper`（期刊投稿/录用/在线发表）、`preprint`（arXiv/bioRxiv/SSRN）、`conference`（口头/海报/摘要）、`thesis`（学位论文答辩/入库）、`code`（公开仓库/模型权重）、`blog`/`other`。每条必须填日期与 URL/证明；`graceCase` 默认 `none`，只有用户明确选择并附证明才可改为四类之一。

## 7. 形式检查：可执行断言

> 纯函数：`formalCheck({patent, disclosure, claims, spec, references, evidence, manifest}) → checks[]`，形状对齐 `src/venue/compliance.ts:23-38`：`{id, level:'error'|'warn', pass, actual, expected, where}`。全部有负例 fixture。

| ID | 断言（机读） | 依据 | 失败码 |
|---|---|---|---|
| F-01 | 权利要求编号 `1..N` 连续、唯一、阿拉伯数字 | 细则 22 | `CLAIM_NUMBERING` |
| F-02 | 独立权利要求恰好 1 项；>1 报 error 并提示单一性/分案 | 细则 24 | `CLAIM_INDEPENDENT_COUNT` |
| F-03 | 独立权利要求位于其从属之前；从属只引用编号更小的权利要求 | 细则 24/25 | `CLAIM_REFERENCE_ORDER` |
| F-04 | 多项从属只择一引用，且不被另一项多项从属引用 | 细则 25 | `CLAIM_MULTI_DEPENDENT` |
| F-05 | 独立权利要求含前序 + 「其特征在于」；从属含「根据权利要求 X 所述」+「其特征在于」 | 细则 24/25 | `CLAIM_FORM` |
| F-06 | 每条权利要求特征至少 1 个存在的说明书段锚点；`coverage = covered/total = 100%` | 专利法 26.4 | `CLAIM_SUPPORT_MISSING` |
| F-07 | 说明书五部分齐全且顺序为 技术领域→背景技术→发明内容→附图说明→具体实施方式 | 细则 20 | `SPEC_SECTION_ORDER` |
| F-08 | 段号 `[0001]..[NNNN]` 连续、无重复/缺口；每段有哈希 | 细则 20（实施） | `SPEC_PARAGRAPH_NUMBERING` |
| F-09 | 摘要（含标点）≤300 字；含名称/领域/问题/方案要点/用途；无商业宣传词；有附图时有摘要附图；附图标记加括号 | 审查指南 2.4 | `ABSTRACT_LIMIT`/`ABSTRACT_CONTENT` |
| F-10 | 附图 `图1..图N` 连续；每图在附图说明中出现；每图在具体实施方式中被引用；标记双向一致 | 细则 21 | `FIGURE_NUMBERING`/`FIGURE_REF_MISMATCH` |
| F-11 | 权利要求术语与说明书术语一致（同一特征名） | 细则 22 | `TERM_INCONSISTENT` |
| F-12 | 对比文件均有公开号+公开日+URL+检索时间；≥1 个 `closest`；矩阵每行（独立权利要求特征）× 每列（对比文件）非空；filing-ready 时全部 `verified:true` | 审查实践 | `PRIOR_ART_INCOMPLETE` |
| F-13 | 每条「有益效果」有 evidence 链接；`measured` 的 artifact 存在且 sha256 匹配 | 项目红线 R2 | `EVIDENCE_MISSING` |
| F-14 | 请求书字段：名称与说明书一致；发明人≥1；申请人名称/地址齐全；费减仅在 `recordNo` 非空时勾选；外国申请时保密审查标记 | 细则 19 | `REQUEST_FIELD_MISSING` |
| F-15 | 公开事件：优先权日前的每条公开，必须落在 6 个月内且 `graceCase` 属四类之一 | 专利法 24 | `NOVELTY_RISK` |
| F-16 | 导出包每个文件哈希与 manifest 一致；PDF/DOCX 存在（或显式 `EXPORT_UNAVAILABLE`）；文本无绝对本地路径 | 项目红线 | `EXPORT_MANIFEST_MISMATCH` |
| F-17 | 文本无占位符：`[TODO]`、`XXX`、`待补`、`TBD` | 项目红线 | `PLACEHOLDER_REMAINS` |
| F-18 | 发明名称 ≤25 字（化学等特殊情况 ≤40，需用户标记） | CNIPA 答复 2020-07-20 | `TITLE_TOO_LONG` |
| F-19 | 权利要求/说明书不得出现「如权利要求……所述」式引用语与商业宣传用语 | 细则 20 | `SPEC_FORBIDDEN_PHRASE` |

**覆盖率定义**：`coverage = |{feature ∈ 独立权利要求特征 : feature.support 非空且锚点存在}| / |独立权利要求特征|`；从属特征单独统计 `warn`。**导出前 coverage 必须 = 1.0**。

**摘要字数实现**：按 Unicode code point 计数（`Array.from(text).length`），含标点；与 CNIPA 咨询「按字数、含标点」一致。

6. 证据：`measured` 链接指向不存在的 artifact → `EVIDENCE_MISSING`；改哈希 → `EVIDENCE_HASH_MISMATCH`。
7. 公开门：`disclosureEvents` 中优先权日前 30 天的 `paper`（`graceCase:none`）→ `NOVELTY_RISK`；改为申请日后 → 通过。
8. 导出：`spec.md/spec.tex/claims.txt/abstract.txt/patent.docx` 均存在；PDF 缺失时返回 `EXPORT_UNAVAILABLE` 并给安装/转换指引（**不得静默成功**）。

### 10.3 优先级

| 优先级 | 内容 | 理由 |
|---|---|---|
| **P0（MVP 必做）** | 领域模型/磁盘布局；交底书；权利要求树；特征-支撑矩阵；说明书五部分+段号；F-01…F-19；DOCX 导出；公开时序门；人工复核门；`srw_patent` + RPC + 专利卡；2 技能 | 没有这些，「写专利」仍为零；其中公开时序门是**防止把可专利内容发出去**的唯一机制 |
| **P1（完整版）** | EPO OPS/Google BigQuery/WIPO 适配器；对比矩阵自动填充；PDF 精排；法律状态/同族；OA 导入答复；费减/保密审查流程化；M6 证据链接入 | 提升效率与证据强度，但不影响「能写出可提交的草稿」 |

**建议顺序**：先修 M5 的三个 P0（runner/`\input`/build 落点，见 00 §12.2，1–2 天）→ **M9a 专利 MVP（45–60 天，可与 M6 并行）** → M6 证据链 → M7 → M8 → M9b。理由：专利不依赖 M6 才能开工（证据可标 `unverifiable`），但越晚做，越可能已经有论文/预印本公开，**新颖性风险随时间单调增加**。

## 11. 结论

- 以用户最终目的为验收标准，当前项目**完成度不是 5/5，而是 4/5 的路径上还缺一整块**；专利不是「M8 的一个小功能」，而是一个独立领域（数据模型、检索、形式合规、导出、公开时序）。
- 本方案的支点是「**结构化真相源 + 可执行形式检查 + 证据链 + 公开时序门**」，与项目已有的「文件即真相源 / 三把尖刀 / 诚实性三件套」同构，不是另起一套。
- **最小可交付**：45–60 人日换来「一个真实发明 → 形式检查 0 error → 可交代理人的 filing 包」，且不编造、不自动提交、不越法律边界。
- **完整闭环**：再加 50–77 人日（检索源、OA、PCT/US、M6 证据链），才能说「写专利」这条主线和其他四条一样，有工具、有门、有验收。
