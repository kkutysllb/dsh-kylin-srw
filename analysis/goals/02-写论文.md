## 4. M6 素材与证明链（尖刀 2：让每个数字/图可回指）

### 4.1 完成定义

- 4 类素材（图/表/伪代码/公式）均可由 spec + metrics 生成，生成物可编译；
- 每个素材在 `materials/manifest.json` 有：生成器哈希、输入（metrics/artifact/spec）哈希、输出哈希、验证状态、插入位置；
- 论文里出现的**每一个量化结论**都能沿「正文 → artifact → inputs → metrics → run」走通；
- 篡改任一输入或产物 → `recompute` 判 `mismatch` → `insert`/`pack` 阻断，恢复后复绿。

### 4.2 数据模型（`<project>/materials/manifest.json`，schemaVersion 1）

```jsonc
{
  "schemaVersion": 1,
  "artifacts": [{
    "id": "fig-arch-01",                       // ^[a-z][a-z0-9-]{1,40}$
    "kind": "figure",                          // figure | table | pseudocode | formula
    "provenance": "derived",                   // measured | derived | literature | illustrative
    "path": "materials/figures/fig-arch-01.tex",
    "generator": { "kind": "script", "path": "materials/gen/plots.mjs", "sha256": "…",
                   "argv": ["--spec", "materials/specs/fig-arch-01.json"], "seed": 42,
                   "fingerprint": { "node": "v24.18.0", "python3": "3.12.2", "sympy": null } },
    "inputs": [{ "kind": "metrics", "path": "experiments/exp-01/runs/r3/metrics.json",
                 "sha256": "…", "selector": "accuracy" }],
    "output": { "sha256": "…", "bytes": 8123 },
    "verification": { "status": "verified",    // verified | mismatch | unverifiable | illustrative
                      "method": "recompute",   // recompute | hash | sympy | structural
                      "checkedAt": "2026-…", "detail": "输出哈希一致" },
    "insertedAt": [{ "file": "paper/sections/03-method.tex", "line": 88,
                     "label": "fig:arch-01", "input": "figs/fig-arch-01.tex",
                     "target": "paper/figs/fig-arch-01.tex", "targetSha256": "…" }],
    "illustrative": { "allowed": false, "watermark": false, "footnote": false }
  }]
}
```

**状态语义**（四级，UI/论文/投稿包统一）：
- `verified`：输入/生成器/输出哈希一致，且复算成功；
- `mismatch`：任一哈希不符、产物/副本缺失或被改 → **阻断**；
- `unverifiable`：缺源、缺工具（sympy/引擎）、跨主机不可达、或结构/人工方法 → 允许插入但**强制脚注**；
- `illustrative`：示意数据（默认拒绝；显式开启后三处标注）。

**关键判据**：环境指纹不一致（node/python 版本变）判 `unverifiable`，**不判 mismatch**——避免把环境漂移误报成数据造假。

### 4.4 与 experiments/metrics 的接口

**契约（M6 只读，M7 负责写）**：

```jsonc
// experiments/<exp>/runs/<run>/metrics.json
{ "schemaVersion": 1, "runId": "exp-01/r3", "tier": "D3",
  "values": { "accuracy": { "value": 0.912, "unit": "", "stderr": 0.004, "n": 3, "seed": 42 },
              "f1": { "value": 0.887 } } }
```

- 选择器：`<exp>/<run>#<metric>`（如 `exp-01/r3#accuracy`）；`inputs[].selector` 必填，缺则 `INVALID`；
- `artifacts.json` 提供 measured 产物的路径 + sha256（0201 M7 任务 7.6 既有约定）；
- **M7 未开工时的补数据通道**：`materials.metrics.import {project, file, provenance:'measured-local'}` 校验形状后复制为 `experiments/manual/<run>/metrics.json` 并写 `run.json`（`source:'manual'`, `importedAt`, `operator`）。这样用户可先用自己的 CSV/JSON 补数据，证明链照常工作；
- 缺 metrics 时 `materials.generate` 报 `NOT_FOUND` 并提示「先导入指标或跑 M7 作业」——**绝不生成占位数据冒充真实**。

### 4.5 生成器与确定性

| 类型 | 模板 | 输入 | 确定性要求 | 验证方法 |
|---|---|---|---|---|
| 表 table | `booktabs` | metrics 选择器 | 列序固定、`%.4g`、无时间戳 | recompute（输出哈希） |
| 图 figure | `pgfplots`（数据曲线）或 `tikz`（架构/流程） | metrics / spec 节点边 | 坐标固定、无随机布局 | recompute |
| 伪代码 pseudocode | `algorithm`+`algorithmic` | spec.steps（agent 填内容） | 纯文本 | structural（`unverifiable`，须 `codeRef`） |
| 公式 formula | `equation`+`\label` | spec.latex + 等价性检查 | 固定精度 | sympy（缺依赖 → `unverifiable`） |

工程纪律：生成器**不调用 LLM**（内容由 agent 写进 spec，生成器只做确定性渲染）；输出不得包含时间戳/绝对路径（否则哈希不稳定）；`LC_ALL=C`、`TZ=UTC`、固定 seed。

### 4.6 插入正文与「数字回指」

- `materials.insert {id, sectionId, position?}`：
  1. 过 G-M1（状态非 mismatch；illustrative 需 allowed）；
  2. 把产物复制到 `paper/figs/<id>.tex` 并记 `targetSha256`；
  3. 在目标节末尾（或标记 `% srw:insert:<id>` 处）追加 `\input{figs/<id>}`，`\label` 由产物内部提供；
  4. 写 `insertedAt`；重复插入按标记去重（幂等）；
- 正文引用用 `Fig.~\ref{fig:arch-01}`；`materials.remove` 删除插入块 + 副本；若用户手改过副本，`verify` 报 `mismatch` 并阻止删除前静默覆盖；
- **数字宏（P1 推荐）**：`materials.numbers` 生成 `paper/generated/srw-numbers.tex`（`\newcommand{\srwacc}{0.912}`）+ `numbers.json`（宏 → selector → 源哈希）；作者在正文写 `\srwacc`；`numbers.audit` 扫描 Results/Experiments 节的裸数字字面量，列为「未溯源数字」（warn），投稿包对 D2/D3 要求 0 条未溯源；
- 编译前门：`compile` 复核所有 `insertedAt[].targetSha256`，任一不符 → `GATE/ARTIFACT_DRIFT`（可检测，不能阻止直接改文件——诚实声明边界）。

### 4.7 复算（recompute）算法

1. 校验输入：逐个 `sha256(磁盘文件) == inputs[].sha256`；不等 → `mismatch`（附首个差异的字节/行摘要），不执行；
2. 校验生成器：`sha256(gen 脚本) == generator.sha256`；缺失 → `unverifiable`，不等 → `mismatch`；
3. 在受护栏的临时目录（`paper/build/recompute/<id>/` 或 OS tmp）以记录的 `argv/env/seed` 运行生成器，超时 120s；
4. 比对 `sha256(新输出)` 与 `output.sha256`：相等 → `verified`；不等 → `mismatch`（文本产物给首 5 行 diff）；
5. 写回 `verification`（状态/时间/指纹/detail）；**不自动改基线**——用户显式 `materials.rebaseline {id, reason}` 才接受新数据（记录审计）；
6. measured 且无生成器：`method:'hash'` 对比 `artifacts.json` 的 sha；跨主机真复算留给 M7。

判定矩阵：

| 情形 | 状态 | 插入 | 投稿包 |
|---|---|---|---|
| 输入/生成器/产物/副本全一致且复算成功 | verified | 允许 | 允许 |
| 任一输入哈希不符 | mismatch | 阻断 | 阻断 |
| 产物或 `paper/figs/*` 副本被改/缺失 | mismatch | 阻断 | 阻断 |
| 生成器/工具缺失、跨主机不可达、结构/人工 | unverifiable | 允许 + 强制脚注 | 允许（checks 记 warn） |
| 指纹不一致 | unverifiable | 允许 + 脚注 | 允许（提示环境漂移） |
| provenance=illustrative | illustrative | 默认阻断；allow 后三处标注 | 同级阻断/标注 |

### 4.8 三个门

| 门 | 触发 | 判定 | 不过后果 |
|---|---|---|---|
| G-M1 溯源门 | 任何 `insert` | 状态 ∈ {verified, unverifiable}（或 illustrative+allowed），inputs 全部可解析 | `GATE` 阻断，返回缺哪个源 |
| G-M2 公式门 | `generate/insert` formula | sympy 数值或符号等价检查通过 | `unverifiable` + 论文脚注「未验证」 |

## 5. 修改循环与投稿（M8）

### 5.1 版本快照与修订 diff

- 扩展快照 manifest（向后兼容，字段可选）：`{kind:'auto'|'manual'|'submission'|'revision', label?, note?, outlineHash, venueHash, materialsHash, pdfSha}`；新增 `paper.snapshot.tag {id,name,note}`；列表返回标签；
- 新 `paper.diff {from,to}`：自实现 Myers 行 diff（零依赖），输出 `{files:[{path,status,hunks:[{aStart,bStart,lines:[{op,text}]}]}],stats}`；持久化 `paper/diffs/<from>__<to>.json`；只 diff 文本（tex/bib/json），PDF 只比页数与 sha；
- 回滚后校验 outline/venue/materials 三者一致性，不一致提示而非静默。

### 5.2 审稿意见 → 响应信

- 数据模型：`reviews/round-<n>/reviews.json` `{round, venueId, reviews:[{reviewer, comments:[{id, text, area}]}]}`；`responses.json` `{items:[{commentId, response, changes:[{snapshotId, file, hunkIndex, note}]}]}`；
- **证据门**：每条 `changes` 必须能在 `diff(baseSnapshot, snapshotId)`（base = 首轮基线快照或上一轮投稿快照）中定位到对应 hunk，否则 `GATE/RESPONSE_UNBACKED` —— 防「编造已修改」；
- `paper.review.export {round, format:'md'|'tex'}` 生成响应信（审稿意见 / 回复 / 修改位置与 diff 摘要 / 快照 id）；camera-ready 走同一 round 结构。

### 5.3 cover letter / highlights / declarations

- `cover-letter.md`：标题/刊物/档位/轮次自动填充；正文（贡献与契合点）由 agent 起草后经 `paper.submission.draft {field,text}` 落盘；刊物事实必须带 `confidence` 标注（unverified 要写「未核定」）；
- `highlights.txt`：3–5 条、每条 ≤100 字符（按刊物模板可调），每条可挂 `outline section id` 作为证据（可选）；
- `declarations.tex`：按 venue `mandatoryStatements`（空则按档位 `profile.statements`）逐项生成；事实来源：数据/代码可得性从 `experiments`/`materials`/repo 路径取，取不到写「需作者确认」并让 pack 在 D2/D3 阻断；补中文 label 别名。

### 5.4 期刊模板与格式检查（激活 4 个死字段）

`paper.format.check {venueId,tier}` 返回与 compliance 同形状 `{id,level,pass,actual,expected,where}`：

| id | 判据 | 数据源 |
|---|---|---|
| template.class | `\documentclass` == venue.documentClass | main.tex |
| template.options | classOptions 为子集 | main.tex |
| pages | `pdfinfo` 页数 ∈ [profile.min, min(venue.pageLimit.regular, profile.max)] | build/main.pdf（`pdfinfo` 本机可用 [实测]） |
| abstract.words | abstract 词数 ≤ venue.abstractWords | main.tex |
| figures/tables/references | 计数 ∈ 档位区间 | 编译输入集合（不是磁盘全文，修 N2） |
| refstyle | bibStyle + 引用命令族（numeric→`\cite`，author-year→`\citep`）匹配 | venue + tex |
| figure.dpi | 栅格图（PNG/JPEG）≥ figureDpi；纯矢量 → pass=undefined | 图片头解析 |
| columns | 由 documentClass 推断（IEEEtran journal/acmart sigconf=2，llncs/ctexart=1）；PDF 实测列数超出本程 | main.tex |

### 5.5 投稿包与 D1–D3 落点

`paper.submission.pack {round?}` → `submissions/<ts>/`：`submission.json`（venue/tier/round/snapshotId/checks/files）、`manuscript.pdf`（当前编译快照）、`cover-letter.md`、`highlights.txt`、`declarations.tex`、`checks.json`、`files.sha256`。

pack 门槛：任一 inserted artifact `mismatch`、任一未解决引用、任一 `[TODO: 待实验数据]` 残留、verified 刊物的 error 级不合规 → `GATE` 拒绝（unverified 刊物只 warn）。

| 能力 | D1 | D2 | D3 |
|---|---|---|---|
| 声明 | 无（可选 data/code） | data/code/limitations | +COI/ethics/contributions（`depth.ts:44,54`） |
| 复现材料 | 脚本清单 | +种子/环境 | +容器/硬件/统计脚本（`depth.ts:35,45,55` 的 repro） |
| 投稿包 | manuscript+cover letter | +highlights+declarations | +复现清单+作者贡献/COI |
| 检查 | 4–6 页/图 2–3/表 1/refs 20–30 | +消融证据 | +显著性/成本证据 |

## 8. 风险与依赖

- **R1 环境**：本机 TeX 四引擎全缺、sympy 缺 [实测] → DoD-1 必须在一台装了 tectonic 的机器/CI 上验收；否则「完成」只能到 ENGINE_MISSING 语义（这正是当前状态）。

- **R3 M7 依赖**：真实指标与跨主机复算要等 M7；M6 先用手工导入通道跑通，M7 落地后自动升级为真复算。

- **R5 中文刊**：声明/附录 label 需中文别名，否则 `cn-journal` D3 结构性缺口（`compliance.ts:115-122`、`registry.ts:83-85`）。
- **R6 审稿文本自由**：响应信门只保证「引用存在」，不保证「改得对」；结论要用户复核。
- **R7 大文件/传输**：manifest 只存路径+哈希；PDF/PNG 走文件系统，避免 RPC 4 MiB 上限。
