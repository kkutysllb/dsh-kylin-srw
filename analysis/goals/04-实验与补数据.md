### 1.3 三条集成事实（设计必须内化）

**F1｜② 级的 `cwd` 陷阱静默吞掉第一条语句。** `ssh_run.execute` 取 `cwd: a.cwd || targets.activePathFor(h.id)`（`…/dsh-ssh-remote/lib/index.js:259`）；`Runner.run` 拼 `cd '~' && <command>`（`lib/exec.js:49-51`）；`cd` 失败后 `&&` 链被跳过，但 `;` 后续照跑、整体 exit 0〔代码事实+实测 P10/P11〕。→ **任何经 `ssh_run` 的派发必须显式传远端绝对 `cwd`，且首句后跟唯一哨兵（如 `echo __SRW_OK__`）**，否则"作业没启动但 UI 看到成功"。

**F2｜② 级 stdout 256 KiB 静默截断。** `defaults.maxStdout=262144`（`exec.js:39`），按尾部裁剪并置 `stdoutTruncated`（`exec.js:64,75`），但 `ssh_run` 输出投影只拼 `stdout+stderr`（`index.js:238-245`），**不暴露截断标记**〔代码事实〕。→ ② 级只做短命令/哨兵；**日志续读、二进制/产物回传、`sha256sum` 校验禁走**，必须走 ①/③ 的结构化 `exec` 与 `tail -c`。

**F3｜环境非开箱即用，"盘点+自举"是独立工作量。** 无 torch、系统 Python 无 pip、`node` 缺席；但 conda base 有 pip/numpy、pypi 可达、CUDA 13.4 可编译〔实测 P5/P6/P8〕。→ MVP 的"最小真实 GPU 作业"用 **nvcc 编译的 vecadd**（不依赖 torch，秒级，仍是真 GPU 计算）；torch/conda 环境创建列为 P1 的 `env.setup`（显式、可审计、默认不自动装）。

## 4. ComputeProvider：三级链、边界与派发纪律

### 4.1 抽象（只暴露可组合原语）

```ts
export interface ComputeProvider {
  readonly kind: 'cm' | 'tool' | 'direct'
  available(): Promise<{ ok: boolean; detail: string }>
  exec(host: HostRef, argv: readonly string[], o?: { cwd?: string; timeoutMs?: number; maxBytes?: number }): Promise<ExecResult>
  tail(host: HostRef, path: string, fromByte: number, maxBytes: number): Promise<{ chunk: Uint8Array; nextByte: number; eof: boolean }>
  put(host: HostRef, remotePath: string, bytes: Uint8Array): Promise<{ sha256: string }>
  get(host: HostRef, remotePath: string, maxBytes: number): Promise<Uint8Array>
}
```

`HostRef` = `{ ref: sha256(hostId)[:8], label, provider }`；**地址/用户名/端口只存在于内存，不落工作区**。

### 4.2 三级链（探测 → 行为 → 限制）

| 级 | 探测（按序短路） | 执行方式 | 今天的结论 | 限制/禁用面 |
|---|---|---|---|---|
| ① cm | `~/{.kcoder,.kcoder-dev,.dsh}/ssh-remote/cm/<id>.sock` 存在 + `ssh -o ControlPath=… -O check`（或直接跑哨兵） | `spawn('ssh', ['-o','ControlPath=<sock>','-o','ControlMaster=no','-o','BatchMode=yes','-p',port,target,'--',cmd])` | **实测可用**（P9），零凭据 | socket 生命周期由宿主插件控制（`ControlPersist` 默认 600s，`connection.js:103`）；消失即降级 |
| ② tool | `ctx.tools.execute` 在且工具表有 `ssh_run` | `ctx.tools.execute({callId,name:'ssh_run',arguments:{hostId,command,cwd},signal})` | 本会话可调用（P10/P11 即此路） | **仅短命令**：F1 静默跳过、F2 256 KiB 截断、返回渲染文本（`index.js:238-245`）非结构化 JSON；**禁用于日志/产物**；绕过 ssh-remote 审批 → 我们的 `submit` 门必须在前 |
| ③ direct | 用户在 SRW 设置填 `identityFile`（仅路径），文件存在且 0600 | 同上 spawn，加 `-i <key>`、`BatchMode=yes` | 未配置（当前无需求） | 第二份配置，UI 明示；**绝不读 `credentials.enc` / 绝不解密密码** |

> `ctx.ssh` 不是多主机注册表（单主机单租约，`0102:604`），不使用；`ctx.jobs` 座位仍未实测（`V-host-facts.md:15` V7 待测）→ **自带文件型 job 表**，不依赖 `ctx.jobs`。

### 4.3 「永不读 credentials.enc」的可执行边界

- 代码层：`src/compute/` 只 import `node:fs/promises`、`node:child_process`、`node:crypto`；不 import 任何 credentials 模块；全文不出现字符串 `credentials.enc`（当前全仓 0 命中，保持）。
- 行为层：① 复用 socket 不建立认证；③ 只用用户给的私钥路径；② 借宿主插件认证，我们只传 hostId。
- 测试门：`tests/compute-security.test.ts` 断言 `src/compute/` 文件内容匹配 `/credentials(\.enc|\.key)/` 为空，并进 `pnpm test:security`。
- 失败姿态：私钥缺失/权限非 0600 → `NO_AUTH` + 引导，**不尝试密码回退**。

### 4.4 hosts.json 只读解析与敏感信息治理

- 只读：`readFile`+`JSON.parse`，**永不写回**（宿主插件 `reload()` 也只读，`hosts.js:131-140`）。
- 解析：按 `hosts.js:35-48` 的字段面（id/host/user/port/identityFile/auth/jump/defaultCwd）本地实现最小子集，不 import 第三方内部模块。
- 脱敏：`run.json` 只存 `{ref: sha256(id)[:8], label}`；日志写入前过 `redact()`（IPv4/IPv6、`user@`、`:port`、`/home/<user>`）；错误只出现 label。**P1 的 hostId 是 IP 形态，禁止直接落盘或当 label 用**。
- 不复制：`hosts.json` 内容不进项目目录、不进 storage、不进导出包。

### 4.5 派发纪律（架构级）

- **脚本先落远端盘**：`put()` 写 `runDir/launch.sh`（由 `spec.entry` + env 白名单生成），审计可见；执行 `bash runDir/launch.sh`（argv，不拼串）。
- **脱离会话**：`launch.sh` 内 `setsid nohup bash runDir/job.sh > run.log 2>&1 & echo $! > run.pid`（V12 已实测，`E4:20-28`）；本地只短轮询（≤10s）。
- **显式终态**：`exit.code`、`done`、可选 `progress.json`；三者齐备且 exit=0 才可能 `succeeded`。
- **断线续读**：本地镜像 + `offset.json`；每次 `tail -c +${offset+1}`，追加后校验「本地末 4 KiB sha256 == 远端末 4 KiB」，不一致则整段重读并记 `logReconciledAt`。
- **判活/取消**：`kill -0 $(cat run.pid)`；pid 缺失但 done 未到且日志增长 → 仍 `running`；三者都判不了 → `unknown`（grace 90s + 连续 2 次）。取消写 `cancel.request`，对 pid 执行 `kill -TERM -<pid>`（setsid 会话首进程，负号杀组），15s 后 `-KILL`，以 `kill -0` 消失为准；不可达 → `interrupted` + `cancelRequested` 下次重试。
- **上限**：`maxHours` 默认 8h；单次读取 4 MiB；日志总量超 `maxLogBytes`（默认 256 MiB）→ `failed(LOG_CAP_EXCEEDED)`，**不静默截断**（对齐 `0102:648`）。

## 6. 「补数据」独立设计

### 6.1 缺口模型（`experiments/<expId>/gaps.json`）

输入四路：① 已确认 spec + D 档阈值（`venue/depth.ts:26-57`）；② runs 完成度；③ `metrics.missing` 与失败 run；④ 未 verified 的 claim。输出条目：

| kind | 判定 | 例 |
|---|---|---|
| `missing-run` / `missing-dataset` / `missing-baseline` | 已确认 spec 的 seeds/datasets/baselines 未达档位 | D2 需基线≥4，已有 2 |
| `missing-metric` | spec.metrics 某指标在 metrics.json 缺失 | flops 2/3 run 缺 |
| `missing-stat` | 档位要求 significance/costAnalysis 但无结果 | D3 配对 t 检验缺失 |
| `outlier` | 稳健 z-score > 3 或偏离同组中位数 > 30% | 同 seed 组 acc=0.1 |
| `failed-run` | 终态 failed/interrupted/unknown 且被 claim 引用 | 唯一 seed 失败 |
| `stale-input` | 数据集哈希/版本变化后未重跑 | registry v2 ≠ run inputs |
| `unverifiable` | `hashPolicy:none` / 证据缺 | 引用它的 claim |

每条带 `blockingClaims[]`、`estGpuHours`、`priority`、`suggestion`。**"补数据补完"= 该文件 P0/P1 为空。**

### 6.2 缺失值、异常值与失败 run 的规则

- **缺失**：不插值、不猜。`metrics.status=partial` + gap；论文中该数字只能 `unverifiable`（强制脚注）或补跑。
- **异常值**：保留原始值；用中位数/MAD 标 `outlier`，**禁止静默删点**；聚合给 `reducer: mean|median` 与剔除规则（`exclude: [runId]` + 理由），`aggregates` 记录 `n` 与剔除清单。
- **失败 run**：进 `failed-run` gap；分母效应显式化（`n_planned / n_ok`）；不允许"只报成功 seed"。
- **重跑**：新 runId、`attempt+1`、`parentRunId` 指向旧 run；旧 run 保留（数据只增不删）。

### 6.3 统计与复算

- `experiments/<expId>/analysis/stats.py`（或 .mjs）由用户/agent 提交，**脚本 sha256 + 种子 + 输入 metrics 哈希**写进 `stats.json`；输出含 `t_stat/p_value/CI/effect_size`（D3）。
- 复算（对齐 M6 `verify.recompute`，`0102:377`）：重跑统计脚本 → 与 claim 的 `value/computed` 比对；改输入一个字节必 mismatch。
- `n<3` 时显著性 → `unverifiable`（**不假 pass**，与 sympy 门"缺依赖 ≠ pass"同构，`0102:343`）。

### 6.4 排期与优先级（`experiments/<expId>/queue.json`）

- 排序：`P0=阻断 claim` > `P1=D 档硬要求` > `P2=成本/显著性分析`；同级按 `estGpuHours` 升序填谷。
- 调度：**单主机串行、单卡并发 1**（不做多机调度，遵守 0102 §2.2 不做清单与 ADR-9）；GPU 全忙 → `queued(NO_FREE_GPU)`，不假跑。
- 预算：`maxHours × 卡数` = GPU-hours；队列总预算超阈值 → 显式确认。

### 6.5 与 M6、论文数字的对接

```
run → metrics.json(sha256) → claims.json(claim↦metric+reducer) → materials(plots/tables 以 metrics 为 inputs)
    → writer 插入正文（G-M1：inputs[].sha256 可解析）→ 投稿视图（completeness = gaps 空 + claims 全 verified）
```

M6 未开工不影响本设计：M7 先产出 `metrics.json + sha256`（`0102:358` 已约定形状）；M6 落地时把 claims 纳入 `manifest` 的 `kind:'number'|'table-cell'` 即可。最小闭环不依赖 M6 UI：`claims.check` 纯函数 + RPC + 工具动作，G-M1 调用它。

## 8. 失败模式与安全

### 8.1 失败模式矩阵（检测 → 状态 → 用户可见动作）

| 失败 | 检测 | 状态 | 动作 |
|---|---|---|---|
| 主机不可达/超时 | probe 超时（ConnectTimeout=15s） | 不提交 | "不可达 + 上次成功时间"；作业保持 `queued`，**不假跑** |
| 认证失败/无 key | ssh exit 255 + `Permission denied` | 不提交 | `NO_AUTH` + 三条通路各自修法（对齐 `0102:688`） |
| 主机移出 hosts.json | 复用前 `resolveHost(ref)` 失败 | 保持原状态 | "主机已不可见"，禁止 cancel 误判 |
| 目录不可写/磁盘不足 | 提交前 `test -w` + `df -Pk` 阈值 | 不提交 | `DISK_LOW`（≥ 预估产物×3 + 1 GiB） |
| GPU 全忙 | 选卡时全部 used/total > 0.8 | `queued` | `NO_FREE_GPU`；空闲后自动转 running |
| OOM | exit 137/134 + 日志含 `out of memory` | `failed(OOM)` | 建议换卡/减 batch；最多 1 次换卡，不无限重试 |
| 脚本语法/入口错 | exit≠0 且日志首 4 KiB 含 `syntax error` | `failed` | 回显前 4 KiB（脱敏） |
| 日志超总量上限 | 字节数 > maxLogBytes | `failed(LOG_CAP_EXCEEDED)` | 明示上限与位置，不静默截断 |
| 断线 | 轮询失败但 pid/日志可判活 | 保持 `running` | 退避轮询；UI 标"连接中断" |
| 插件重启 | 启动扫 run.json 非终态 | 保持原状态 | reconcile 恢复；远端进程不随插件退出（setsid） |
| 取消时不可达 | cancel 写入失败 | `interrupted`+`cancelRequested` | 下次 reconcile 重试；提示可能仍在跑 |
| 指标缺失/坏格式 | metrics 缺失/JSON 坏/schema 错 | `failed` 或 `partial` | 进 gap；claim 只能 unverifiable |
| 采集时文件被改 | 远端 sha256 ≠ 已记录 | `failed(ARTIFACT_CHANGED)` | 重采；不覆盖旧哈希 |
| 远端时钟偏差 | `date +%s` 与本地差 > 120s | 仅警告 | 墙钟上限用远端时刻，记偏差 |

### 8.2 安全与审批

- **审批矩阵**（`src/tools.ts:103-120` 的 `ASK_TABLE` 扩展）：`srw_experiment` 的 `submit`/`cancel`/`rerun`/`env.setup` → **ask**（固定英文 reason + 中英 displayReason）；`hosts`/`status`/`logs`/`collect`/`dataset.register` → 豁免。submit 会在远端执行用户代码，是本插件风险最高的动作。与 00 §8.2"IO 工具豁免、门在服务层"一致，同时修正 0201 §8.2 文档矛盾（P1-7）。
- **命令注入**：远端执行一律 argv 数组 + `bash <script>`；用户值只进 `job.env`（单引号转义）或 `spec.json`，**绝不做字符串插值进命令**；脚本先落盘再执行。单测覆盖分号、`&&`、`||`、`$()`、反引号、换行与 Unicode。
- **主机信息泄露**：hosts.json 只读不复制；run/日志/导出只含 `host.ref(hash)+label`；日志与错误统一 `redact()`；导出包不含地址/用户名/端口。hostId 是 IP 形态（P1），**禁止当 label 用**。
- **长任务/租约**：作业全部脱离会话（`0102:642-650`）；轮询 ≤10s；插件 dispose 不杀远端，下次启动 reconcile。**不挂 `ctx.ssh` 租约**（30s fail + 远端清理，`0102:605`）。
- **成本/离线**：GPU-hours 预算进 spec；离线只读本地（历史 run/指标/claims），提交转 `queued` 标 `offline`；本地写作/阅读不受影响（`0102:686`）。
- **法务/学术**：数据集 `license/redistributable` 必填；导出包不打包不可再分发数据；ADR-6 示意数据红线不因 M7 放宽——`allowIllustrative` 仍只在 M6 三处标注下使用。

### 9.2 依赖顺序与 MVP

