## 0. 一页纸结论

1. **这是一个定位清楚、文档密度极高、工程纪律罕见地强的单人/小团队项目**：提交集中在 3 天（2026-10-04 → 10-06）共 97 个 commit，工作区维护延续到 10-09，交付 M0–M5 六个里程碑；`src/` 11,111 行、测试 4,266 行/163 例、设计文档 3,026 行。
2. **产品命题**：不做第二个 Mimir，做 **DSH（桌面端）+ 麒麟 QiLin（Web 端）双通道**的科研工作台——**读**（段落锚定、可校验的双语精读产物）、**写**（按刊物分级的 LaTeX 生产线）、**证**（素材/数字的真实性证明链）。
3. **当前真实状态**：M0–M5（地基、项目、文献、订阅、精读、论文线）已实现并有活体验收记录；**M6 素材与证明链、M7 实验与算力、M8 投稿与发布尚未开工**。README 状态行仍停在「M2 完成」，与交付事实脱节。
4. **验证现状（本次实测）**：`pnpm typecheck` 0 诊断；`pnpm test` **163/163 通过**（61.7s）；`smoke` 全 PASS、负例 4/4 变红。测试数量与质量在同类插件里属于上游水平，但**覆盖集中在纯逻辑与存储，装配层、HTTP 传输层、真实 TeX 编译、客户端 UI、打包产物运行时基本裸奔**。
5. **最严重的发现（P0）**：论文线的**真实进程 runner 从未接线**——`SrwService` 构造 `WriterService` 时没传 `run`，`src/writer/run.ts` 的 `nodeRun` 全仓零引用，发布包 `lib/index.js` 里 `child_process` 出现 **0 次**。后果是 **M5 的「编译」在生产环境恒 `ENGINE_MISSING`，即使装了 tectonic 也不生效**；163 个测试全绿是因为 writer 测试全部注入假 runner。同类「接线级」缺陷还有 `\input` 清单与大纲脱钩（静默丢节）。
6. **P0 数据正确性**：`RateGate` 把限速账本永久缓存在内存、锁内也只读缓存 → **跨进程/换根后的限速唯一性失效**（探针实测应 ≥500ms 的间隔只隔 21ms），对 arXiv「1 请求/3 秒」是真实封禁风险；`OpenAlex` 摘要恒为空（读了不存在的 `abstract` 字段，应为 `abstract_inverted_index`）。
7. **精读（M4）是完成度最高的差异化模块**：块级基底层 + 呈现层段落装配分离、`srcHash` 结构性防幻觉、哈希迁移、译注版 PDF 体例，架构经得起推敲。但存在 4 个确定性缺陷（PDF 页眉/页码只写末页、整宽元素阅读序颠倒、页缘带吞标题、无文本层静默空产物）与一批「token 不友好」的失败语义。
8. **论文线（M5）设计正确、落地有三处硬伤**：runner 未接（P0）、`\input` 与大纲脱钩（P0）、真实引擎输出落 `paper/` 而代码只认 `paper/build/main.pdf`（P1，导致 `pdfWritten` 恒 false、快照无 PDF）。venue 的「unverified + sources 强制、未核定只建议」三件套是真正的亮点。
9. **安全与宿主契约整体是「清醒的」**：SSRF 四步 + 钉死 IP、fail-closed 的 `ctx.fs.contains` 路径护栏、RPC 同源栅栏、双通道发布面用 40+ 条冒烟断言固化。主要漏洞在策略缝隙：`root.set` 的 containment 自检恒真、`project.remove` 不校验是否项目就递归删除、审批矩阵与架构文档不一致。
10. **结论**：这是一个**架构判断力明显高于平均、但「最后一公里」尚未收口**的项目。它的价值不在代码行数，而在把三个学术上最难的位置（逐段精读产物、分级写作、真实性证明链）想清楚并落了前两个；下一步应先把 M5 的三处接线硬伤和两个数据正确性 bug 修掉，再进入 M6/M7。

## 2. 技术形态：一个 npm 包，两个宿主通道

### 2.1 单包双键

`package.json` 同时声明 `dsh` 与 `qilin` 两键，内容逐字相同：

- `bundle.patch` 指向单个 `cordis.patch.yml`（麒麟的 `bundlePatchOf` 只认 string）；
- `client.platform = "web"`，`client.inject` 五个 `@deepseek-ai/dsh-client-*` 包名；
- `peerDependencies` 里所有 `@deepseek-ai/*` 写 `*`（版本门含 prerelease）；
- **引擎包绝不进 `dependencies`**（麒麟会拒绝整个 profile）；
- Host 侧**零 `@deepseek-ai/*` 运行时 import**（只有 `import type`），框架行为靠 `inject` 服务与内联重放。

这些不是口头纪律，而是 `scripts/smoke-plugin.mjs` 的可执行断言（含 4 条负例自检，本次实测全 PASS / 4 红）。

### 2.2 Host / Client 两层 inject 不能混

- **Host inject**（`src/index.ts:30-41`）是「编排存在性契约」：10 个服务名——`connection`、`webServer`、`storageDomain`、`workspaceRegistry`、`settings`、`fs`、`agents`、`tools`、`skills`、`systemPrompt`。多写一个目标 profile 未挂载的服务（例如 `schedule`）会让插件**永久 pending**（E3 实证）。
- **Client inject**（`src/client/index.tsx:18-34`）是「需要加载/注入的客户端 bundle 服务名」：14 个，含 E1 保留的 `sidebarRight`/`documentPreviews`/`uiSession`/`conversation`。
- `schedule` **故意不进 Host inject**，改用「属性访问 → `ctx.reflect.get`」两级读 + `NO_PROVIDER` 降级（0204 勘误 1），从而在 web profile 缺 schedule 时仍可「建订阅、手动跑」。

### 2.3 构建与发布

- `scripts/build.mjs`：`tsc` 出声明到 `lib/types/`；esbuild 打 Host ESM（`@deepseek-ai/*` external）与 Client CJS 自注册（`window.__ModuleLoader__.load({id, factory})`，react external）。
- 两个运行时坑被构建脚本兜住：
  - pdfjs 打进 host bundle 后，Node 侧 fake worker 解析到 bundle 同目录 → 复制 `pdf.worker.mjs`；
  - pdfkit 标准字体 AFM 走 `require('#standard-fonts/*')`，Node 禁止 imports 指向 node_modules → 复制字体到 `lib/pdfkit-standard-fonts/` 并映射。
- 实测产物：`lib/index.js` **4.2 MB**（pdfjs 自包含）、`lib/client.js` 110 KB、`lib/` 97 个受版本控制文件。**没有 CI**，`lib/` 与源的产物一致性靠人工。

## 4. 装配与运行机制

### 4.1 `apply()` 做了什么（`src/index.ts:53-150`）

1. `ctx.effect(...)` 内 `SrwService.open(ctx, config)`：打开 `srw_index` storage 域（失败降级不阻断），挂 workspace store。
2. `ctx.reflect.provide('srw', service)`（ADR-19）：让别的插件未来可 inject。
3. `systemPrompt.section` 注入 644 字能力通告（设计目标是「只说工具表说不出的工作流约束」）。
4. 注册包内技能：定位 `skills/manifest.json`（构建后 `lib/`、tsx 直跑 `src/`），`registerBundledSkills` 读 manifest、剥 frontmatter、`ctx.skills.register(source:'runtime', resourceBase)`。
5. 根 Agent 工具挂载：对 `agents.roots()` 中每个 root 调 `mountTools`，并监听 `agent/created` / `agent/disposed`；在 agent fiber 上 `ctx.effect` 注册 5 个工具，卸载时逆序回收。
6. `tools/pre-execute` 审批钩子：先 `await next()`，只有 downstream 为 `allow` 时才可能把结果替换成 `ask`；`callerFrom` 从 `exec.agent.session` 取 `sessionId/cwd`，只对已挂载工具生效。
7. 注册 RPC `/dsh-kylin-srw`（webServer 前缀路由 + `connection.requestRejection` 栅栏 + 4 MiB body 上限）。
8. 返回 disposer：逆序回收工具、owned effect、RPC、service。

> 潜在小问题：`ctx.effect` 的返回值被再次包进外层 disposer 时，内层已由 fiber 自动回收，存在双重 dispose 的可能（`service.dispose()` 已做 `index=undefined` 幂等，实测二次 dispose 安全）。

### 4.2 RPC 层

- 通道：`/dsh-kylin-srw`（`src/rpc.ts:19`），POST + JSON；先过宿主 `requestRejection`（同源/Origin/Host/浏览器鉴权），再校验 method/endpoint。
- 信封：请求 `{type:'client-request', rpcId, method, payload}`；响应 `{type:'server-response', rpcId, result}`；`result` 为 `{ok:true,value}` 或 `{ok:false,error:{code,message,details}}`。**`details` 必须是对象**，否则 vendored 客户端把业务错误显示成类型错误（0203 真网踩坑）。
- **47 个 case**（含 8 个 `diag.*` 探针端点）：root/project、literature、watch、reading、paper.*、venue.*、overview。
- 校验是手写的（`reqString ≤5000`、`optNumber` 通用整数），**没有 zod**；zod 只用于 storage domain spec。业务校验在 service 层。
- 长任务**同步占 HTTP**（compile 300s×3 轮、translate 300s 工具超时），与 0102 ADR-13「立即返回 jobId + 轮询」不符；也没有取消通道。

### 4.3 Tool 层：5 个工具、35 个动作

| 工具 | 动作 | 审批 |
|---|---|---|
| `srw_project` | list/create/open/remove | create/remove ask |
| `srw_literature` | search/import/pdf/bibtex/lib | import/pdf ask |
| `srw_watch` | list/create/remove/pause/resume/run | create/remove ask |
| `srw_read` | status/extract/translate/notes/export | **全豁免** |
| `srw_paper` | state/venue.list/venue.apply/scaffold/outline.get/outline.prompt/outline.save/outline.confirm/section.write/compile/cite.audit/refs.append/snapshot.list/snapshot.restore/compliance | **全豁免** |

审批文案分离为「`reason` 审计文本（不随语言变）+ `displayReason` 双语渲染」。工具结果遵守 **lossless JSON** 纪律（禁 undefined、JSON 往返等价），并有回归门——这是从桌面端真机踩坑换来的契约。

**审批矩阵与 0102 §8.2 / 同族 automation 不一致**：架构文档写「写需审批 / 启动耗 token 需审批」，实现把 `srw_read`、`srw_paper` 全豁免，`literature.bibtex`（写 `refs.bib`）、`watch.resume`（重建周期任务）也豁免。设计理由（「授权来自会话显式意图」）成立，但应把文档改成「IO 工具豁免、门在服务层」，而不是让两边长期矛盾。

### 4.4 Client 层

- 单文件 `WorkbenchView`（1,418 行、约 40 个 `useState`）承载 8 张卡：项目头/项目列表/流水线/文献/订阅/精读/论文/诊断；没有视图路由，也没有 0102 规划的 7 视图。
- 右栏硬约束处理正确：主区 keyed 面板一旦占主区，引擎右栏/文档预览失效（E1 实证），因此面板自绘预览；「翻译/导读」通过 `selectPanel(null)` 让出主区 → 400ms 等会话面挂载 → `retain + binding + conversation.input.for().setDraft/submit`，两路都断则复制到剪贴板。这是全项目与宿主耦合最深、也最贴合宿主真实时序的一段代码。
- i18n 只注册了侧栏一个词（`nav`），面板/设置页全部硬编码中文。
- `styles.ts` 缺 `srw-list`/`srw-item`/`.srw-badge.bad` 三个被大量使用的类 → 列表无样式、撤稿/错误徽章不变红。
- 诊断视图 `DiagView` 仍在生产面板折叠卡里，且内置开发机绝对路径 `/Users/libing/.../README.md`，已打进 `lib/client.js`。

### 4.5 技能层

4 个技能经 manifest 注册：`research-idea`（选题卡）、`literature-triage`（三源检索/入库）、`paper-drafting`（D1–D3 分档写作纪律）、`venue-fit`（合规差距清单）。技能与工具的 action 名一致，纪律写进 SKILL.md（如「G1 归用户点头」「数字禁止编造」「编译失败最多自主修 3 轮」）。0102 规划的另外 4 个（close-reading / materials-proof / experiment-design / repro-audit）随 M6/M7 分期。

## 5. 数据模型：文件是真相源

### 5.1 两级工作区

- **科研总根** = 一个引擎 workspace（用户用原生目录选择器选）；
- **研究项目** = 总根下一个 slug 目录 + `.srw/project.json`；
- `storageDomain` 只存「哪个根、当前活动项目、项目列表投影」——**任何可由文件重建的数据都不进 storage**。

理由（ADR-3/ADR-4）：面板一套表 + 引擎一套表必然漂移；项目作为子目录才能跨项目共享文献、且 agent 无面板也能维护。

### 5.2 实际磁盘布局

```
<root>/
  .srw/root.json                 # 总根配置（politeMailto 等；多数字段暂无消费者）
  .srw/rate-ledger.json          # 限速账本（跨进程文件锁）
  <project>/
    .srw/project.json            # schemaVersion/slug/title/stage/targetVenue?/depthTier?
    .srw/venue.json              # 刊物实例 {venueId, tier}
    .srw/outline.json            # 大纲一级真相源（status/revision/sections[].file）
    .srw/watch.json              # 订阅（revision + STALE）
    literature/
      library.json               # 条目索引（revision + STALE）
      pdf/<citekey>.pdf
      notes/
      readings/                  # 骨架创建，但实际未使用
    reading/<paperKey>/          # 精读域（真实落点）
      source_map.json            # 块表 + extractor 指纹
      sources.json               # 源文 sidecar（0205 文档写的 meta.json 不存在）
      paper.md                   # 双语正文 + 块锚
      cache.json                 # cacheKey 四元组 → 译文
      glossary.json              # 术语表
      notes.json                 # 导读 + 每节速览/精读备注
    readings/<YYYY-MM-DD>/<paperKey>.pdf   # 译注版 PDF 按日归档
    paper/
      main.tex  refs.bib  sections/*.tex
      build/                     # 编译日志（PDF 落点与真实引擎不一致，见 §7.5）
      snapshots/<ts>/            # tex + bib + pdf + manifest(哈希)
    experiments/  materials/      # 骨架占位，M6/M7 未实现
```

**布局不一致点**：骨架建 `literature/readings`，实际精读产物在 `reading/` 与 `readings/`；三个相近目录名（`reading` / `readings` / `literature/readings`）容易让维护者踩坑，文档（0102 §6.2 的 `literature/readings/<citekey>/`）也未回写。

### 5.3 并发与冲突

- `library.json` / `watch.json` 用 `revision` + `STALE` 拒写 + `tmp→rename` 原子落盘。
- 但 STALE 是 **check-then-write**，无锁、无 0102 承诺的 mtime/内容哈希比对；两个自动化路径并发时，一次冲突就把整次抓取变成 error。
- `project.json` 直接 `writeFile`，非原子；`create` 是 `stat → mkdir`，存在 TOCTOU。
- `paper/refs.bib` 追加不取锁（对照组 RateGate 有锁）。
- `srw_index` 域 version 恒 1（宿主 storage 无迁移机制，只能加可选字段 + `.default()`）。

## 6. 已交付领域逐域分析

### 6.1 M1 · 工作区与项目（`src/workspace`, `src/host.ts`, `src/store.ts`）

**流程**：`root.set` → 路径自检 → 写 `root.json` → 写 storage 全局 → 内存收编；`project.create` → 建 slug 目录 + 7 个子目录 + `project.json`；`list` 实扫目录，坏 `project.json` 跳过而不是抛错（用户手工目录不会被面板弄坏）。

**亮点**：
- **fail-closed 路径护栏**：`assertInsideRoot` 用 `fs.resolve → fs.contains` 目标对象语义，能力缺失直接抛，绝不「无护栏也放行」；`resolveWorkspacePath` 是纯拼接、不是护栏——这条认知来自上一轮调研的自我勘误。
- **降级不阻断**：storage 打不开时插件仍可用，根来自 patch config、活动项目只在内存。
- **诊断即真值表**：`diag.caps` / `diag.contains` 把宿主能力探成可复现证据。

**缺陷**：
- `currentRoot()` 让 **patch config 优先于 storage**，但面板换根只写 storage → 若部署时 patch `rootDir` 非空，换根「成功返回但无效」。
- `root.set` 的 containment 自检是 `assertInsideRoot(fs, path, path)`——**恒真式**，只证明 resolve 可用，没有判断「这个目录是否适合当总根」。
- `project.remove` 不校验 `.srw/project.json` 就 `rm -rf`；若总根选得过宽（如 home），删除一个恰好匹配 slug 的普通目录会整目录递归删除。
- 换根/删项目不清 `activeProject` 与 `project_cache`。
- `root.json` 的 `offlineMode`/`defaultLangPair`/`allowIllustrative` 无消费者；离线只来自 patch config，但错误文案让用户「在面板关闭离线模式」，面板没有这个开关。

### 6.2 M2 · 文献通路（`src/literature/`）

**流程**：三源检索（arXiv Atom / OpenAlex / Crossref）→ 归一化 → 三级身份去重（DOI → arXiv id → 标题+年份）→ `library.json` → 撤稿检查 → PDF 下载 → BibTeX。

**安全设计（真正的工程亮点）**：
- **SSRF 四步自实现**：`parseFetchUrl`（仅 http/https、拒 URL 内凭据、长度 ≤2048）→ `resolvePublicAddresses`（任一地址非公网即整组拒绝）→ `createPinnedLookup`（连接钉死已校验 IP，防 DNS 重绑定）→ 拒绝跨源重定向；叠加域名白名单。
- **RateGate**：按域令牌桶 + ±20% 抖动 + 429/503 退避 + `Retry-After` + 连续 5 次熔断；跨进程唯一性用 `O_CREAT|O_EXCL` 文件锁 + 陈旧锁强破（4 进程实测）。
- **PDF 落盘**：流式 tmp → sha256 → rename，字节上限 + deadline。

**亮点**：
- `candidateFromInput` 的容形 + `fillThin` 只补空缺 + upsert 二次自愈——对「agent 会剪参数」这一现实做了正确响应（0203 真网踩坑 8/9）。
- 跨源身份折叠：arXiv 自赋 DOI `10.48550/arxiv.*` 折叠为 arxivId，解决同文再造 5 条重复的真问题。
- 撤稿/勘误分型：`updated-by.type` 白名单 + 无 type 保守归勘误，避免误标红阻断引用。

**已复核的缺陷**：
- **P0 RateGate 缓存**（`rate-gate.ts:84-98,107-114`）：`loadLedger` 只在 cache 为 null 时读盘，`mutate` 锁内也只读缓存 → 两实例交替 acquire 时实际间隔可低至 21ms（应 ≥500ms），且 `lastRequestAt` 会被回退；换根后缓存也不失效，新根继承旧根账本。
- **P0 OpenAlex 摘要恒空**（`openalex.ts:66`）：读 `work['abstract']`，官方 Work 对象只有 `abstract_inverted_index`；fixture 也没有该字段，测试结构性发现不了。OpenAlex 的 `is_retracted` 也未被消费。
- **P1 非 arXiv OA PDF 取不到**：默认白名单只有 5 个 API 域，且重定向只允许同 host http→https → OpenAlex 的 `best_oa_location.pdf_url`（出版商域）必然 `SSRF_BLOCKED`。这是产品缺口（安全侧是收紧的），与 0203 实录「只有 arXiv PDF 成功」一致。
- **P1 title 键 year 漂移**（`identity.ts:27-29` + `library.ts:160-167`）：标题键含 year，year 自愈又按 identityKey 反查 → 先入 year:0 再入同题 year:2025 会永久产生两条重复，自愈永不触发。
- **P1 `resolveDoi` 裸 fetch**（`crossref.ts:111-114`）无 deadline/UA，可无限阻塞；`assertNotRetracted` 零调用者，撤稿门只在 bibtex 内联。
- **P1 验收不可达**：0203 验收 #6「假 DOI → UNRESOLVED」对应的 `resolveDoi` 无 RPC、无工具动作，是死 API。
- **P2** PDF 无 content-type/魔数门（200 的 HTML 错误页会当 PDF 落盘）、只钉 `addresses[0]`、DNS 解析在 deadline 之外；`isPublicIp` 漏判非规范 IPv6 与若干保留网段（当前不可达，仅纵深防御债）。
- **P2** 退避口径不一致：注释/文档写 `2^n×1s`，实现是 `n²×1s`；抖动 ±20% 使 arXiv 最小间隔可到 2.4s < 官方 3s。
- **P2** 全库撤稿核查 60s 窗口、串行、失败静默；`archived` 状态从未写入；`corrigendum` 通知只落盘、面板不展示。

### 6.3 M3 · 定期抓取（`src/watch/`）

**核心设计（ADR-8 的正确落地）**：`ctx.schedule` 只是「往已有会话投消息」，**不能新建根 agent**；因此**触发与执行分离**——时钟负责投一条自包含 prompt 唤醒会话，抓取本身是 host 确定性代码（零 token、可审计、可精确重试）。绑定失败不回滚订阅，返回 `hint` 并保留「可行手动 run / 补排程」的降级路径。

**亮点**：
- 只存 `scheduleId`，不复制宿主时钟字段 → 宿主页与面板不会双写漂移。
- 时钟服务用「属性访问 → `ctx.reflect.get`」两级读，缺席归一 `NO_PROVIDER`，订阅仍可建可手动跑（0204 的 Cordis 围栏教训）。
- `lastResult` 让「静默停滞」变成可见信号。

**缺陷/风险**：
- 每次到期都会**唤醒一个会话跑一轮 agent**（有 LLM 成本）；0204「抓取本身零 token」只对 host 执行体成立，文档应显式标注「每 tick ≈ 1 agent turn」。
- `record()` 遇并发 STALE 会把「已成功抓取」变成 error；`run` 无并发互斥。
- 面板 `resume` 只传 `{id}`，无根会话时创建 → `boundSessionId` 缺失 → 「补排程」永远「无可绑会话」，与 0204「面板 resume 时选择会话」不符。
- `everySeconds` 非法静默回退 86400，与其余「非法即 INVALID」风格不一致（但已成契约）。
- `corrigendum` 未进 `WatchLiterature` 接口，watch 结果丢该信号。

### 6.4 M4 · 精读（`src/reading/`）——完成度最高的差异化模块

**流水线**：

```
PDF → pdfjs legacy getTextContent（取坐标）
    → detectGutter（x 中心直方图，两簇 + gutter 判双栏）
    → 逐栏 buildLines（y 容差分桶、x 升序、间距补空格）
    → groupBlocks（行距/字号）→ kindOf（13 类，实际产出 7 类）
    → refineBlocks（全页语境：furniture/title/references/figlabel/caption）
    → buildSourceMap（稳定 ID p{page}-b{idx} + srcHash）+ migrateBlocks（按 srcHash 认领译文）
    → translateBlocks（≤4000 字/块、句切、并发 3、deadline+退避、术语硬约束）
    → paper.md（块锚 + 三态校验）→ paragraphs 段落装配 → 面板/译注版 PDF
    → 分析层 notes（全文导读 + 每节速览/精读备注，可恢复、分批）
```

**架构上最正确的决策**：**块级基底层与呈现层分离**。块是 `source_map`/`srcHash`/缓存/迁移/校验的唯一锚；`paragraphs.ts` 只做阅读体验。改呈现不重译、不破坏 verify；「整篇逐段呈现」的用户指令因此没有推翻底层设计。

**结构性防幻觉**：块锚 + 源文哈希（译文不参与哈希）→ verify 重算得出 `verified / mismatch / orphan / missing`。活体验收（vaswani 15 页真双栏、99 块）里手改源文一个词，校验从 ✓99 变 ✓98/⚠1，复原回 ✓99——约束在真环境成立。

**其他亮点**：
- 稳定 ID + 哈希迁移：换切分算法不丢用户数据，重复哈希按序配对，救不回标 orphan 而不是丢弃。
- 启发式来自真语料回归：References 三形态、figlabel 收紧、罗马数字节标题，不是拍脑袋。
- 译注版 PDF 体例工程：封面信息表/阅读指南/导读/速览与备注盒/附录 A–D/图内标注；CJK 字体回退 + glyph 子集内嵌；用**自己的抽取器回读产物**做验收。
- 长任务走引擎车道：面板只发起，翻译/导读在会话里可见可中断、续发续译。

**确定性缺陷（已实测）**：
1. **译注版 PDF 页眉/页码只作用于最后一页**：`PDFDocument` 未启用 `bufferPages`（`pdfdoc.ts:149`），pdfkit 在 `addPage()` 时 flush 页面，末尾 `bufferedPageRange()` 只剩当前页 → `for` 只跑一次，页眉永不写，页脚写成「1 / 1」。修复 1 行：`bufferPages: true`。
2. **整宽元素阅读序颠倒**：跨栏 item 被追加到页尾（`extract.ts:407-411`），整宽标题成为 `p1-b13`（页内最后），物理却在页顶。
3. **62pt 页缘带可吞标题**：标题先判 `furniture`，`title` 重选又跳过 furniture（`extract.ts:272-274,282`）→ 整篇无 title。
4. **无文本层静默空产物**：`source_map.pages` 由块反推得 0（`source-map.ts:66`），extract 对 0 块不报错，违反 0102「提示用户 OCR/不可引用」的承诺。
5. **测试套件被 60s 定时器绑架**：`timeoutOf` 没有「已 abort 快速失败」分支（`timeout.ts:30-33`），单个取消用例 32ms，进程要等 60s 才退出（本次全量测试 61.7s 的主因）。

**token/续跑风险**：
- 一批里任一失败在写 cache 前抛错 → 该批已成功译文全部丢弃、重试重烧。
- `finish.reason='length'` 不当失败 → 截断译文静默入缓存。
- 长块句切后 `Promise.all` 绕过 Limiter，实际并发 = concurrency × 片数。
- 术语表变更整表清 cache（与计划「定向失效」冲突）；译后术语违规只静默替换、`violations` 丢弃。
- `budget.ts` / `recommend.ts` / `formula.ts` 仅测试引用，预算门/G2 门/公式策略**未接线**。

### 6.5 M5 · 论文线与刊物分级（`src/writer/`, `src/venue/`）

**流水线**：venue 选择 → D1–D3 → scaffold（`main.tex` + `sections/` + `refs.bib`）→ outline（一级真相源）→ **G1 确认门** → section.write → compile → texlog 解析（79 列折行回接/括号栈/`l.N`）→ cite-audit → refs.append → 编译成功自动快照 → compliance。

**亮点**：
- **venue 诚实性三件套**（真尖刀）：schema 强制 `confidence` + `sources`；`unverified` 只 warn 不阻断；`pass: undefined` 表示「事实缺失 ≠ 不通过」。这从机制上堵住「AI 编造期刊要求」。
- **G1 门硬编码在服务层**（`sectionWrite → assertConfirmed`），不是提示词请求；工具描述同时写「用户没点头不要 confirm」——门 + 纪律双保险。
- **快照哈希防线**：manifest 记 sha256，restore 逐文件比对，不一致 `CORRUPT` 拒绝恢复；快照里没有的节文件回滚时清除并报告。
- **79 列折行回接**：判据是「被消费段原始长度」而不是合并结果，这是单测当场抓出的坑。
- **agent 车道**：大纲/正文由会话 Agent 起草，插件只做 IO + 门 + 编译，零私有 LLM 调用。

**三处硬伤（已复核）**：
1. **P0 runner 未接线**：`src/service.ts:118-123` 构造 `WriterService` 只传 `fs/rootDir/libraryEntry`；`WriterService` 用 `deps.run ?? throwNoRunner`（`writer/service.ts:256,270,408`）；`nodeRun`（`run.ts:8`）全仓无 import，`lib/index.js` 里 `child_process` 0 次。→ 引擎探测把抛错吞成「不可用」→ **生产环境编译永远 `ENGINE_MISSING`**。**这是全项目最严重缺陷**：M5 的核心承诺在真实宿主上不可用，而 163 个测试因全用假 runner 而全绿。
2. **P0 `\input` 与 outline 脱钩**：`scaffold.ts:70` 写死输入清单后永不重写，`outline.save`（`service.ts:182-207`）又按 agent 标题另分配文件。标题与 `sectionOrder` 不完全同名时，正文写进不被编译的文件、编译进空占位节——**编译仍成功但静默丢节**，compliance 还会假阳性。
3. **P1 `build/` 落点错**：命令无 `-output-directory`（`engine.ts:37-47`），cwd 是 `paper/`，真实引擎把 PDF 写在 `paper/`；代码只认 `paper/build/main.pdf`（`service.ts:272,396`；`snapshot.ts:37`）→ `pdfWritten` 恒 false、快照永不含 PDF、面板恒「无产物」。假引擎测试直接写 `build/main.pdf`，恰好固化了错误假设。

**其他缺陷**：
- 快照 restore 绕过路径护栏（`snapshot.ts:95-129` 用 node:fs 按 manifest 路径键读写，无 containment）；篡改 manifest 为 `../escape.txt` 可越界写（已复现）。
- **G1 死路（UI 可达）**：`emptyOutline` 不分配 file，`confirm` 不校验，面板 scaffold 后即可点「确认大纲」→ 之后 `section.write` 恒 `INVALID 未绑定文件`。
- texlog 两处脆弱：79 列回接会把「恰好 79 列的行 + `!` 错误首行」并成一行 → `errors=[]`；`l.N` 只往后看 6 行，pdflatex `File ... not found` 形态首错丢行号、`l.5` 错挂到 Emergency stop。
- `escapeLatex` 反斜杠输出 `\textbackslash\{\}`（多一对字面花括号）。
- `PathSafetyError` 不是 `ServiceError` → 越界在 RPC/工具层变 `internal`，丢失「安全拒绝」语义。
- venue 的 `pageLimit/columns/figureDpi/referenceStyle` 四字段零消费者；声明/附录只认英文 label → `cn-journal` 的 D3 声明项结构性永远「缺」。
- cite-audit 只认 `\cite/\nocite`，不认 `\citep/\citet/\autocite`；`toBibtex` 输出 `venue` 而非 `journal/booktitle`，会议条目书目信息可能缺项。
- `engineCache` 无 TTL，装引擎后须重载插件；compile 同步阻塞 300s×3 轮。

### 9.2 测试策略的优点

- **注入 seam 设计干净**：`RunPort`（TeX）、`LlmPort`（翻译）、`schedule` fake、`fs` fake——测试不联网、不烧 token、不需要真引擎。
- **fixture 优先**：手造单栏/双栏 PDF、arXiv Atom、OpenAlex/Crossref JSON、真实形态 TeX 日志。
- **回归门有「反向证明」**：lossless JSON、`no undefined`、双通道 4 条负例、跨进程文件锁 4×5。
- **文档记录了「为什么」**：每条勘误都写清踩坑与判据（79 列判据、WARNING 形态、`l.N` 就近、Cordis 围栏），可维护性远高于平均。

### 9.3 覆盖缺口（按风险）

1. **`src/index.ts` 零测试**：装配顺序、`reflect.provide`、工具挂载、审批钩子、卸载全部靠人工验收。
2. **HTTP 传输层零测试**：`serveRpcRequest` 未导出；401/403/405/415/413、body 上限、UTF-8 chunk bug 无用例。
3. **`SrwService.writer` 真实装配零测试**：所有 writer 测试注入假 runner → P0 逃逸。
4. **client 零测试**：40 个 useState、RPC 解包、`sendToCurrentAgent` 两条路径、i18n 全无回归。
5. **打包产物运行时零测试**：pdfjs worker、pdfkit 字体 shim 只在活体验收暴露过（M4-1/M4-3）。
6. **安全策略面**：`root.set` 优先级、`remove` 校验、审批矩阵无用例。
7. **并发**：除 RateGate 外，library/watch/项目创建均无并发测试。

> 一句话：**测试很好地保护了「纯逻辑」，但没有保护「接线」**——而这次发现的 P0 全部在接线上。

## 13. 结论：怎么理解这个项目

**它不是一个「半成品 Demo」，而是一个「主体已建成、关键阀门未打开」的系统。**

- **架构判断力**：双通道一等地、文件即真相源、窗口/门/降级矩阵、三把尖刀取舍、ADR 与一手证据——这些是很多成熟团队也未必做得出的判断；11k 行里没有明显的「为了快而乱写」。
- **工程纪律**：里程碑计划 → bite-sized 任务 → 一任务一提交 → 实施实录含勘误 → 活体验收；`pnpm check` 全绿才提交。产品文档 3,026 行与代码同等重要。
- **真实短板**：**自动化测试保护了纯逻辑，却没有保护装配与接线**；而目前最严重的两个缺陷（writer runner、`\input`）恰好都在接线层。其次，文档跑在实现前面，读者按文档会高估完成度。
- **可辩护性**：精读模块已经证明「结构性防幻觉」不是 PPT——真论文、真 LLM、手改源段、校验灯翻转，整条链走通了。刊物分级的诚实性三件套也是真机制。这两点是项目最值钱的资产。
- **风险**：M6/M7 是真正的工程量（证明链、GPU 编排），也是「实事求是」命题的落点；如果先扩功能而不修 M5 的接线，会把「编译不可用」带进后续所有里程碑。

**如果只做三件事**：① 接上 `nodeRun` 并加真实装配测试；② 让 `\input` 由 outline 驱动 + 统一 build 落点；③ 修 RateGate 缓存。这三件分别恢复「写得出来」「写得对」「抓得安全」，是继续投入 M6/M7 之前的最低门槛。
