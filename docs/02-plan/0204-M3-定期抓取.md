# 0204 · M3 定期抓取与无人值守

承接 0201 §M3 与 0102 §10。**修订（2026-10-05，用户指令）**：定期抓取的时钟**绑定宿主内置
「自动化任务」插件**（`ctx.schedule` = packages/schedule + tool-schedule + ui-schedule，
DSH 与麒麟双通道内置、重启保留、带跨会话管理页），不另造时钟。0102 ADR-8 的「自建轻量
时钟」与「B 车道 agents.create 派发」撤下——schedule 投递进**既有会话**正是本需求的
设计用途：唤醒会话里的 agent 调 `srw_watch run`，抓取本身仍是我的 host 确定性代码。

## 0. 执行约定（承接 0202/0203）

- 每任务一提交，`pnpm check` 全绿后**先读结果再 commit**。
- fixture 测试优先；真网只在收尾验收。版本恒 0.0.x；**不打 tag**。
- 无损 JSON 纪律（勘误 7）；上游输入形状不可信（勘误 8/9）。

## 1. 架构定位（修订版）

| 职责 | 归属 | 理由 |
|---|---|---|
| **触发**（何时抓） | 内置自动化任务 `ctx.schedule`：订阅创建时同步建一条 schedule 任务，prompt 自包含（「调 srw_watch run」），到期投递进绑定会话 | UI 免费获得（可见/可改/可删/运行记录）；时钟语义（不补发=at-most-once）免费；双通道内置 |
| **执行**（怎么抓） | 我的 host 代码：`search → importEntries`（去重幂等 + 元数据自愈）→ lastResult 落账 | 确定性、限速礼貌、失败精确重试；抓取本身零 token |
| **管理** | 面板订阅卡 + `srw_watch` 工具 + 宿主「自动化任务」页三处可达 | 面板管订阅本体；宿主页管时钟；agent 管全流程 |

**投递目标会话**：agent 建订阅 → 绑定创建者会话；面板建订阅 → 绑定最新根会话，
无可绑会话则「已建未排程」（面板明示，先开会话再 resume 即绑定）。会话被删 →
schedule 投递失败只 warn（E3 已知）→ 面板 lastResult 停滞即信号，resume 重建绑定。

**审批语义**：订阅 create/remove = **ask**（建订阅即授权周期性写库，值得问一次）；
`run`（含 schedule 唤醒的那次调用）= **豁免**——授权发生在建订阅时，唤醒轮若再问
则无人值守必卡死。pause/resume/list 豁免。

## 2. 存储定位

订阅落 **`<root>/.srw/watch.json`**（与 rate-ledger 同款：工作区文件、原子写、过
`assertInsideRoot`；不动 srw_index 域 layout）。形状 `{schemaVersion:1, revision, subs:[]}`，
坏 JSON 抛 INVALID。时钟任务本体存在宿主 schedule 存储（不复制其字段，只存绑定 id）。

```ts
interface WatchSub {
  id: string                    // sub-<base36>
  project: string               // 目标项目 slug
  source: 'arxiv' | 'openalex' | 'crossref'
  query: string
  everySeconds: number          // ≥900（15 分钟地板；宿主 every≥60 之上再收紧）
  enabled: boolean
  createdAt: string
  boundSessionId?: string       // schedule 投递目标
  scheduleId?: string           // 绑定成功才有；pause 即删任务、resume 重建
  lastRunAt?: string
  lastResult?: { at: string; kind: 'ok' | 'error'; fresh?: number; error?: string }
}
```

**踩坑与勘误（重要度排序）**：
1. **Cordis 围栏两刀**：第三方 patch 行插件对未 inject 服务的**属性访问直接抛错**（`cannot get property "schedule" without inject`），且 `ctx.reflect.get` 才是围栏外的全局注册表读法——两级读法（属性→reflect.get）+ 缺席归一 NO_PROVIDER 降级「未排程」。能力探测（diag.ts probe）的 try/catch 惯式由此再次证明必要。
2. **schedule 服务默认不在 web profile**：`@qilin/experimental-schedule-bundle` 是可选 bundle（三行 patch：schedule + ui-schedule + time-context），要写进 profile `package.json` 的 `qilin.profile.bundles`。DSH 桌面/麒麟生产内置口径由用户确认；本插件对缺席 profile 的行为=订阅可建可手动跑，绑定时降级提示。
3. enabled-未排程的订阅需要「补排程」按钮（暂停→恢复的两步太绕）——降级路径必须有一键回到正轨的 UI。
