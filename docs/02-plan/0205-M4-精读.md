# 0205 · M4 精读（尖刀 1 / R6）

承接 0201 §M4 与 0102 §7.1。目标：产出**可 diff、可迁移、可校验**的双语阅读产物
（`paper.md` + `source_map.json` + `glossary.json`），译文永远绑定真实源段——结构性
防幻觉，不靠提示词祈祷。

## 0. 执行约定（承接 0202/0203/0204）

- 每任务一提交，`pnpm check` 全绿后**先读结果再 commit**。
- fixture 优先（手造单栏/双栏 PDF）；真 PDF 验收用库里现成的 `vaswani2017-attention`
  （15 页双栏真论文）。版本恒 0.0.x；不打 tag。
- 无损 JSON / 上游形状不可信 / 报错先审自己代码（勘误 7/8/9 + 0204 勘误 4）。
- 宿主缺的能力**自建**（0102 §7.1.2 一手核对）：PDF 抽取自带 `pdfjs-dist` legacy
  Node build；只有 `llm.stream`（无 complete，用 BlockAssembler）；无 p-limit/p-retry
  （并发闸/退避自建）；GenerateOptions 无 timeout（deadline 融合自建）。
- LLM 经 `ctx.reflect.get('llm')` 通道（0204 勘误 1 的围栏结论），缺席 → 翻译降级提示。

## 1. 产物与磁盘布局

```
<root>/<project>/reading/<citekey>/
  source_map.json   # 块表：id/kind/order/page/bbox/srcHash/quality/translation 元数据
  paper.md          # 双语正文：`<!-- srw:p3-b2 -->` 锚 + 三态（verified/mismatch/orphan）
  glossary.json     # 术语表（硬约束：命中强制用指定译名）
  cache.json        # { cacheKey: { text, model, at } }，cacheKey=sha256(zh+model+srcHash+glossaryHash)
  meta.json         # 抽取器指纹（name/version/pdf sha256/pages）→ 切分版本变化触发块迁移
```

块模型（0102 §7.1.1）：`p{page}-b{index}`、kind 12 类、`srcHash=sha256(normalize(src))`
（折叠空白+连字符+NFKC）、quality 三级 ok/suspicious/degraded。

### 附记三（用户指令，56b4fde）：整篇逐段呈现，不是 chunk 浏览器

**指令**：精读是把整篇**逐段**精读，不是抽成 chunk 逐块浏览；双语要整篇呈现为 PDF。

- 病根：抽取块（行组粒度）被直接当阅读单元——面板与 PDF 都是「块 ID+徽章+
  源文+译文」的 chunk 卡片流，阅读体验碎片化。
- 修法：**呈现层段落装配** `paragraphs.ts`——前块未收句（无句末标点）则续段
  合并（跨块/跨栏/跨页自然接续；行尾连字去拼、CJK 邻接不加空格）；标题/图注
  永不并入。段状态取段内最坏。**块级基底层不动**：source_map/srcHash/缓存/
  verify 全部照旧——不重译、不迁移，校验语义与增量续译完全保留。
- 归档 PDF 重写为**连续双语正文**：标题/标题行分级排版，原文段（灰）+ 译文段
  （黑）连续流；verified 段零 chunk 痕迹，只有问题段亮 `[id] ⚠` 警示行。
- 面板同改段落流，块 ID 退到 hover title。

### 附记四（用户指令 + 样例对照）：精读的终点是「译注版」，不只是双语

**指令**：用户先指出既往工作区里有完成过的精读成果让我对照自查（"你先看看
再考虑你的实现有什么问题"），随后给出样例——《递归自我改进综述
（arXiv:2607.07663v2）中文精读译注版》。该样例即精读产物的验收标准。

**自查（对照样例的真实差距，非猜测）**：

- 我的产物是"翻译器"：逐段双语就到头了；译注版要求**分析层**——全文导读、
  每节【本节速览】、◆精读备注（要点/概念/论证/证据/评述），这些"怎么读"的
  内容一行都没有。
- 抽取质量缺陷在用户真实数据上量化过（pepar-review 两篇，501 块）：p1 首块
  是页眉日期（"September, 2026"）→ `firstOnPageOne` 规则落空 → **全文没有
  title 块**（kind 直方图 para:270/heading:30，title:0）；图内标注碎片
  （"Which Cup?"、"Block Under"）被当正文翻译（垃圾进正文 + 白烧 token）；
  62% 块 <60 字符；参考文献段照译（译注版体例明确要求**英文原样保留**）。
- PDF 是裸的双语流；译注版要求封面信息表、阅读指南、页眉、图表清单、
  术语对照表、免责说明。

**修法（本轮全部落地）**：

- **抽取版面二次判别**（extract.ts `refineBlocks`）：页缘 62pt 内短行 →
  `furniture`（日期/license/页码）；p1 前 8 块里字号最大且显著大于正文者
  重判 `title`（块才看得到全页语境，kindOf 单看自身注定错）；`References`
  行之后全部 → `reference`；孤立单行碎片（≤60 字符、无句末标点、上下间隙
  均 >2.6×正文字号、同栏、附近有图注）→ `figlabel`；`Figure N:` 句式 →
  `caption`。`ExtractedBlock` 补 `size`（块字号）供判别。
- **翻译纪律**：`UNTRANSLATED_KINDS`（furniture/figlabel/reference）不进翻
  译管道——status 的 pendingIds、remaining、状态统计全部按"可译块"
  （`translatable`）计算；prompt 体例强化：数字零误差、`[12]`/`§3.1`/
  `Fig. 2` 保留原形、系统名保留英文、术语首现括注英文。重抽走 migrate：
  新 kind 生效、译文元数据按 srcHash 救回。
- **分析层**（notes.ts + `srw_read` 新 `notes` 动作）：宿主 LLM 逐节生成
  【本节速览】+ ◆精读备注，另生成全文导读（类型判定/一句话概括/要解决的
  问题/章节地图/如果只记三件事）；notes.json 落盘，**可恢复**——失败重跑
  只补缺失节，`limit`（默认 6）分批 → agent 车道逐批可见进度。输出是字段
  行约定（非 JSON——LLM 的 JSON 可靠性不够支撑渲染）。
- **译注版 PDF**（pdfdoc.ts 重写）：封面（中文标题大字 + 英文原题 + 信息表
  + 免责）→ 阅读指南 → 全文导读 → 正文（标题/标题行分级 + 原文灰/译文黑，
  每节【本节速览】盒 + 节尾◆精读备注盒，图注下挂「图内标注」行，问题段
  才亮 ⚠）→ 附录 A 图表清单 / B 术语对照表 / C 参考文献英文原样 /
  D 译注体例与免责说明 → 页眉（`<标题>（paperKey）中文精读译注版`）+ 页码。
- **面板**：精读卡新增「导读/备注」按钮（引擎车道，同翻译）；状态行显示

**验收**：`pnpm check` 全绿（142 测试；新增 refineBlocks 版面判别 6 例、
