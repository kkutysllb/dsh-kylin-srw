# 0206 · M5 论文线与刊物分级（R4/R5）

承接 0201 §M5 与 0102 §7.3。目标：**一条贯通的 LaTeX 通道**——骨架 → 大纲（一级
真相源 + G1 确认门）→ 正文 → 编译（错误定位到行）→ 快照与回滚，全程不离开面板；
外加**刊物要求 schema + 深度档位 D1/D2/D3** 的三个落点（大纲/实验检查/合规检查），
刊物事实一律带 `confidence`/`sources`——未核定的只建议不阻断。

## 0. 执行约定（承接 0202–0205）

- 每任务一提交，`pnpm check` 全绿后**先读结果再 commit**；版本恒 0.0.x，不打 tag。
- 宿主缺的能力自建；LLM 走 `ctx.reflect.get('llm')` 通道；**大纲/正文生成必须走
  agent 车道**（用户指令：所有功能与引擎结合，不许插件私有后台执行）——面板与
  工具只发起，宿主 LLM 调用由会话里的 Agent 经 `srw_paper` 完成。
- TeX 引擎探测与编译是**进程执行**（插件运行在宿主 Node 进程内，`node:child_process`
  可用；文件操作仍过 `assertInsideRoot` 护栏）。本机四引擎全缺（0102 §9 实测）→
  编译测试用**注入 runner**（假引擎）+ 真实日志 fixture；活体真编译等装 tectonic 后
  单独补验（`brew install tectonic`，不代装系统软件）。
- `writer → venue` 单向依赖（0102 §4.1）；`venue/` 只依赖 `core/`（纯函数）。

## 1. 产物与磁盘布局（0102 §6.2 已定，M5 落地这些）

```
<root>/<project>/
  .srw/
    project.json        # 增补：venueId / depthTier（目标刊物与档位）
    venue.json          # 刊物要求实例（apply 后落盘；confidence/sources 随行）
    outline.json        # 大纲一级真相源：{ schemaVersion, status: draft|confirmed,
                        #   confirmedAt?, revision, sections: [{id, title, intent,
                        #   targetWords, status: draft|confirmed}] }
  paper/
    main.tex            # 骨架（按 venue 模板生成；sections/\input）
    refs.bib            # 文献库（cite-audit 追加的落点）
    sections/*.tex      # 分节正文（大纲 section ↔ 文件一一对应）
    build/              # 编译产物（pdf/log/aux）
    snapshots/<ts>/     # 编译成功留档：main.tex + sections/ + refs.bib + build/*.pdf + manifest.json
```

  / `section.write`（按节写正文，G1 过了才放行）/ `compile` / `citeAudit` /

  会话显式意图授权，同 srw_read 口径）。

## 4. 明确不做（本程）

- 远端编译（`ctx.ssh` 三级链是 M7 的事）；LaTeX 语法 lint/chktex；PDF 预览（build/
  产物落盘即可，用宿主/系统打开）；正文生成的质量模型（分档目标字数只是提示词约束）；
  投稿视图（M8）；刊物事实的自动采集（人工核定走 sources）。

## 5. 风险与本程对策

- **本机无 TeX 引擎**：注入 runner 让全链可测；面板引导安装；不代装。
- **venue 事实失真**（RISK-7）：registry 种子全部 `confidence: "unverified"` +
  注明来源占位——只会"建议"，人工核定后才可能阻断（M8 投稿视图做核定 UI）。
- **79 列折行解析漏接**：fixture 用真实 tectonic/pdflatex 日志行宽形态造例。
