# 0201 · 实施计划

**Goal:** 把 [0102 技术架构](../01-tech/0102-技术架构.md) 的 R1–R8 落成一个可安装、可验收、双通道的科研工作台插件（`dsh-kylin-srw`）。

**Architecture:** 单包双键（`dsh` + `qilin`）；Host 侧 `src/` 领域模块 + `rpc.ts` + `tools.ts` + `skills/`，Client 侧一个主区 keyed 面板（7 视图）；**文件系统是真相源**，`storageDomain` 只存索引/缓存/队列；远程算力复用引擎 `ctx.ssh` 家族。

**Tech Stack:** Node ≥ 22.19 / TypeScript 5 / esbuild（Host ESM + Client CJS 自注册双 bundle）/ `node:test` + `tsx` / React（external，走 shell 静态模块表）/ 宿主服务：`workspaceRegistry`、`storageDomain`、`slots`、`settings`、`llm`、`agentDefaultModel`、`web`、`ssh`、`schedule`（可选）。

> 文档定位：这是**总体实施计划**（里程碑、任务边界、验收门、风险）。执行约定见 §1：每个里程碑**开工前**另出一份任务级详细计划（bite-sized + 完整代码），本文件只给到「可验收的任务粒度」，避免对尚未验证的宿主面编写无法落地的代码。

## 1. 执行约定

1. **先验证后编码**：M0 的四个实验（E1–E4）未出结论，不进入 M1。实验记录落 `docs/03-verify/E{n}-*.md`。
2. **每个里程碑一份详细计划**：开工前产 `docs/02-plan/02XX-M{n}-*.md`，粒度＝「一个动作 2–5 分钟」，含完整代码、命令与预期输出（沿 writing-plans 规范）。
3. **TDD 优先**：Host 侧纯逻辑（源适配、去重、块模型、限速器、生命周期状态机、合规检查、证明链）必须先写失败测试。
4. **小步提交**：一个任务一个提交，提交信息 `feat(field): …`；每个里程碑结束跑全量 `pnpm check` + `pnpm smoke`。
5. **双通道不退让**：任何功能合并前必须过 `scripts/smoke-dual-host.mjs`（M0 建立）。
6. **产物随仓提交**：`lib/` 是分发包的一部分（沿 dsh-plugins 约定「零构建链插件直接提交产物」），CI 断言产物与源一致。
7. **不动引擎源码**：任何针对 QiLin/DSH 的改动 = 换方案的信号，不是发 PR。
8. **红线不可协商**：ADR-6（默认禁止示意数据 / 公式门 / 数字必须有 artifact 指针）在任何里程碑都不打折。
9. **验收必须可复现**：每个 DoD 都要有一条**能贴进终端的命令**与预期输出，不接受「人工看一眼」。
