## 0. 结论速览（六条）

1. **生态巨大，但"科研工作台"只有一个真对手**：dsh 插件目录 ✅ 实测 `13,217` 个可装包（另拒绝 `15,539` 个），其中与科研相关的约 142 个、论文类 76 个、arXiv 20 个、精读 5 个。**唯一覆盖全流程的是 `dsh-mimir`**（542★、33 天 27 个版本）；其余全是单点插件。
2. **Mimir 是 dsh-only，这是结构性空档** ✅：`dsh-mimir@0.21.0` 的 `package.json` 只有 `dsh` 键、**没有 `qilin` 键**，client inject 全是 `@deepseek-ai/dsh-*`。麒麟插件管理器只认原生 `qilin.*` 键 → Mimir 在麒麟通道不挂载 client。**双通道是我们不需要抢跑就领先的一条。**
3. **"双语"不空，"逐段精读"才空** ✅：我原以为无人做双语，实测发现 `dsh-bilingual-reader`（划词翻译，选段级、不落地产物）、`@onpeople/dsh-academic-research`（双语写作辅助，纯工具无 UI）、`dsh-pdf-translate`（保版式整文翻译）。**没有任何一个产出"段落锚定 + 可溯源块 ID + 术语表 + 增量重译"的离线精读产物。**
4. **"按期刊分级写作"是真空白** ✅：目录里 `journal template` 类 0 命中；Mimir 的 venue 只是"格式简报 + 模板注册"，不是按刊物级别驱动的写作深度管线。**机器可读的刊物要求 schema 业界也没有**（◐ 缺少即证据，未核实）。
5. **伪代码生成 0 命中** ✅；**公式验证（sympy 数值/符号比对）业界普遍未做** ◐——素材"真实性门"是第二把可辩护的尖刀（Mimir 只有 figure 上传/转换，没有证明链）。
6. **宿主给的地基比预想好** ✅：工作区注册表、原生目录选择器、slot/sidebar-right/documentPreview、`ctx.settings`、`ctx.storageDomain`、`ctx.schedule`、`ctx.llm`+`agentDefaultModel.currentSelection()`、`ctx.web`+代理、`ctx.ssh`（引擎原生 SSH 作为 fs/subprocess/sandbox provider）全部可复用；**必须自建的是"工作区之上的研究项目实体""PDF 获取与解析""精读产物""实验编排与真实性门"。**

### 2.3 架构（✅ 读其 `docs/architecture.md`）

- **分层**：`index.ts`（挂载/路由/生命周期）→ `service.ts`（**84 个 `@Remote`，零逻辑**）→ `services/`（每域一模块，纯逻辑留在 `src/*.ts`）→ `store.ts`。
- **存储**：单一 `research_wiki` domain **v2，10 张表**（papers/ideas/claims/projects/experiments/servers/jobs/figures/events/venue_watches），**additive-only** 演进；`events` 是 append-only 账本，驱动手记与"认知引擎"。
- **双通道推送**：请求/响应走 Typert Remote，实时性走 **SSE `/research/events`**（`domain/changed` → 面板 400 ms 去抖、2 s 上限，重连做全量 resync）。
- **HTTP 权限模型**（值得抄）：写路由要求 `Origin` 与 `Host` 完全同源；读/下载路由**仅回环**（Host 必须是 localhost/127.0.0.1/[::1]，存在 Origin 时必须匹配）→ 防 DNS rebinding；反代裸露时按设计保持回环。
- **远程作业生命周期契约**（值得抄）：`queued → running → succeeded|failed`，外加三种"**未观测到结果**"的终态 `cancelled` / `interrupted` / `unknown`（30 分钟时长上限、4 MiB 捕获上限→显式 `failed` 而非静默截断）。
- **长任务取消**：`linkLongTask` 合并"面板取消 / 宿主 dispose / RPC 超时"三条终止路径。

### 2.4 它已覆盖 vs 未覆盖（决定我们的战场）

| 需求（你的原始清单） | Mimir | 判定 |
|---|---|---|
| 定期下载相关论文 | ✅ arXiv 订阅（每日 25 篇/查询、`seenIds` 差集封顶 500、3 s 礼貌间隔、退避） | 已覆盖，**但只有 arXiv**，无 bioRxiv/SSRN/会议页 |
| 配置工作区总路径 + 子路径研究 | ◐ `workspaceDir`（默认 `.research`）+ 面板内项目 CRUD | 部分：项目是面板内实体，**不是引擎工作区** |
| 全流程论文撰写/修改 | ✅ Overleaf 式（编辑→编译→预览→一键 AI 修复）+ 快照回滚 | **强项，必须正面对标** |
| 按期刊登记不同深度 | ⚠ venue 模板（CVPR/NeurIPS/ACL/IEEE/ACM + 自定义 `.cls`）+"format-to-venue" | 只有**格式简报**，没有分级写作深度 |
| 精读 + 双语逐段 | ❌ 只有 reading-notes 面板 + `paper-deai`（写作去 AI 味，非阅读） | **空白 → 第一把尖刀** |
| 插图/公式/伪代码/数据"实事求是" | ⚠ figure 上传/组织/插入、metrics→图；无 TikZ/伪代码/公式生成，**无真实性约束** | **第二把尖刀：证明链** |
| 远程 GPU + 按论文设计实验 | ✅ `server_list/check`（TCP→`ssh nvidia-smi` 两段探测）+ 批式 ssh 作业（submit/list/delete，超时+缓冲上限） | 强项，**但 ssh-only，无 Slurm/PBS/K8s** |
| 双通道 dsh + 麒麟 | ❌ **无 `qilin` 键**（✅ 实测） | **结构性优势** |

### 2.5 它的已知短板（◐ repo/架构文档自陈 + 目录）

无端到端测试（只有单测 + 装配加载）；LaTeX 日志按单行解析、**79 列折行未回接**；`reviewer.provider` 不做跨模型；单 overlay 入口而非原生多标签工作台；npm 落后仓库约 10 天。

**结论**：Mimir 是"一个人 33 天做出来的九视图大而全"，它的强项（论文工作室、GPU 探测、订阅）我们**不必重复造**，但它的三个缺口（**逐段双语精读 / 分级写作 / 素材真实性证明链**）恰好是学术上最难、也最值钱的位置。

### 4.2 发现与筛选

| 对象 | 机制 | 借鉴点 |
|---|---|---|

## 7. 结论：差异化定位（按"可辩护强度"排序）

**强（对手结构性缺失）**
1. **双通道一等公民**：一份代码同时装 DSH 与麒麟（`dsh`+`qilin` 双键、零 `@deepseek-ai/*` 运行时导入、client inject 用 `@deepseek-ai/dsh-client-*` 由 `dshCompatModuleId` 重映射）。Mimir 与几乎全部竞品都是 dsh-only。
2. **段落锚定的双语精读产物**：`paper.md` + `source_map.json`（稳定块 ID + 页码锚）+ 术语表 + 增量重译缓存。现状是划词（bilingual-reader）、整文保版式翻译（dsh-pdf-translate）、agent preset（paper-tutor）——**没有"可 diff、可迁移、可校验的阅读产物"**。
3. **素材真实性证明链**：每个图/表/数字必须指向**真实数据文件 + 生成脚本**，重跑比对哈希；公式用 sympy 做数值/符号等价验证，过不了就标"未验证"。伪代码生成 0 竞品（✅ 实测）；公式验证业界普遍未做（◐）。

**中（有人做，但我们可以做得更成体系）**
4. **按刊物分级的写作深度管线** + **机器可读的 venue 要求 schema**（`{venue, track, page_limit, abstract_words, section_order, reference_style, figure_dpi, mandatory_statements}` + 违规项机读输出，能挂 `aclpubcheck` 就挂）。
5. **一条贯通的 LaTeX 通道**（编辑→编译→诊断行可点→lint→引用真伪→快照），现状碎在 4 个插件里。
6. **科研总根 + 子路径项目**两级模型（引擎只有 workspace 一级；Mimir 的项目是面板内实体）。
7. **通用 GPU 编排**（Slurm/PBS/K8s/裸 ssh 统一作业 spec + 指标与产物归集）——现状只有 ssh（Mimir）或厂商锁定（scnet）。

**弱/不建议作为卖点（生态已过密，应复用）**
arXiv 检索、PDF 翻译整文、OCR/版面抽取、GPU 监控看板、调度器、Zotero 互操作、PPTs、记忆/RAG。

**一句话定位**：
> 不做第二个 Mimir。做**双通道的、可溯源的**科研工作台：**读**（逐段双语精读，产物可 diff）+ **写**（按刊物分级的论文生产线）+ **证**（素材与实验的数字都必须能指回真实产物），算力复用引擎原生 SSH 与已有 GPU 主机。

## 8. 待拍板（进入方案设计前必须定的口径）

1. **定位取舍**：走"完整工作台对标 Mimir"（九视图级工程量）还是"两把尖刀 + 复用生态"（精读产物 + 真实性证明链 + 分级写作，其余接现成插件）？我建议后者。
2. **双通道优先级**：DSH 与麒麟同时一等公民（默认，成本=双宿主冒烟+DSH 缺的 client 包降级），还是先 DSH、麒麟跟随？
3. **依赖策略**：对生态插件做"**能力探测 + 可选依赖 + 内置最小降级**"（我建议），还是零外部依赖全自建？
4. **工作区模型**：科研总根 = 一个引擎 workspace、子路径 = 研究项目（我建议），还是"总根 + 每项目一个 workspace"？项目元数据落产品 store 还是 `<项目>/.research/project.json`（agent 无面板也能维护）？
5. **精读产物形态**：段落对齐 Markdown + `source_map.json`（我建议，离线可迁移）+ 可选导出"保版式双语 PDF"（后期）？默认语言对与术语表来源？
6. **刊物分级**：先做哪 2~3 个（IEEEtran / acmart / Elsevier cas-dc / LNCS / 中文 ctex+GB/T 7714）？"内容深度"的判定维度（篇幅/章节完备度/实验与消融/图表数/参考文献数）？是否本轮就自建 venue schema？
7. **真实性红线**：完全禁止示意实验数据（只认真实产物），还是允许但强制标注？公式是否强制过 sympy 验证门？每个数字是否强制有 artifact 指针？
8. **算力通路**：复用 `dsh-ssh-remote` + 引擎 `ctx.ssh` 驱动你已有的 `26训练`/`74推理`（我建议），还是内置 Slurm/K8s 适配层？调度走 `ctx.schedule`、`dsh-cron` 还是自建（`dsh-kylin-automation` 无编程接口）？
9. **UI 形态**：先做 §5.3 的三个验证实验，再定"主区多视图 / 右侧栏标签 / overlay"（这决定右栏能力是否可用）。
10. **定时抓取范围**：arXiv 分类 + 主题（OpenAlex/S2）+ 会议页 + bioRxiv/SSRN？频率与礼貌限速（arXiv 硬约束 1 请求/3 秒）？入库与提醒方式？

## 勘误（由 [0102 技术架构](0102-技术架构.md) 的宿主源码复核修订，2026-10-04）

本文件 §5 的宿主能力面来自第一轮快速扫读，逐行复核后有 4 处需要更正。**以下以 0102 为准**：

| 位置 | 原文 | 更正 |

| §5.1 定时 | `ctx.schedule`（`create/list/catalog/history/delete/update`） | ✅ API 存在且双通道同构，但**语义被低估**：`create(sessionId, …)` **只能把消息投递进既有会话**（`sessionId` 必填、投递时恢复该会话的 agent），**不能派发全新根 agent 运行**，且**不补发**错过的时间点（`packages/schedule/schedule/src/{index,runtime,storage}.ts`）。派发全新根 agent 要用 `ctx.agents.withoutInitiator(() => ctx.agents.create(…))` + `followup` |
| §5.1 远程执行 | 「引擎原生 `ctx.ssh` 家族…远程 fs/进程/终端/沙箱四个 provider」 | ✅ provider 存在，但 `ctx.ssh` 是**单主机 + 单租约 + 部署拥有配置**的 PTC 通道（不是主机注册表）；多主机 + 凭据 + ControlMaster 的事实标准是 **`dsh-ssh-remote` 的 `<home>/ssh-remote/hosts.json`**，而该插件**不暴露任何 ctx 服务**（只能读文件 / 只回环 HTTP / `ctx.tools.execute('ssh_run')`）。且 `fs-ssh` 依赖的 `ctx.fs` 在 **DSH 侧是子集**（缺 `writeBytes`/`createDirectory`/`remove`/`move`） |

另有 2 处**补充**（原文未提，但影响架构）：

1. **零 `@deepseek-ai/*` 运行时导入**与**浏览器静态模块表只有 9 个词**（react 系 4 + `@deepseek-ai/cordis` + `dsh-client-store`/`-ui-slots`/`-ui-primitives`/`-ui-dockkit`）——第三方 client bundle 的硬约束；
