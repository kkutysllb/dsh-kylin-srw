## 0. 一页纸摘要

**定位**：不做第二个 Mimir。做**双通道的、可溯源的**科研工作台，三条主线：

> **读**（段落锚定的双语精读产物，可 diff 可迁移）+ **写**（按刊物分级的论文生产线）+ **证**（每个图/表/数字/公式都能指回真实产物）

**形态**：一个 npm 包 `dsh-kylin-srw`，`package.json` 同时声明 `dsh` 与 `qilin` 两键（✅ 同族 `dsh-kylin-vibe` / `dsh-kylin-automation` 同款做法），Host 侧注册服务 / RPC / agent 工具 / 技能 / 定时抓取，Client 侧注册主区 keyed 面板（7 视图）。

**数据**：**文件系统是真相源**（`<科研总根>/<项目>/.srw/*.json` + `literature/` + `paper/` + `experiments/` + `materials/`），`storageDomain` 只存跨项目的索引、缓存、订阅与作业队列——**刻意只保留一套注册表**（0101 §2.5 的教训：两套表必然漂移）。

**复用**：工作区注册表、原生目录选择器、槽位/右栏/文档预览、`ctx.settings`、`ctx.storageDomain`、`ctx.schedule`、`ctx.llm` + 当前模型、`ctx.web`、**引擎原生 `ctx.ssh` 家族**（远端已有 provision 好的执行世界）。

**自建**（真正的工程量，也是护城河）：研究项目实体 · 文献获取与入库 · **精读产物** · **素材证明链** · **刊物要求 schema 与深度档位** · 实验编排与指标归集。

## 2. 定位与边界

### 2.1 做什么（三条主线）

| 主线 | 具体交付 | 为什么值得做（0101 §7 的可辩护性） |
|---|---|---|
| **读** | 段落锚定 + 块 ID + 术语表 + 增量重译的**离线精读产物** | 竞品只有划词翻译（`dsh-bilingual-reader`）、整文保版式翻译（`dsh-pdf-translate`）、agent preset（`dsh-paper-tutor`）——**没有可 diff、可迁移、可校验的阅读产物** ✅ |
| **写** | 一条贯通的 LaTeX 通道 + **刊物要求 schema** + **深度档位** | 生态碎成 4 个插件（编译/lint/公式/批注），**端到端无人做**；按刊分级是真空白 ✅ |
| **证** | 素材证明链（artifact 指针 + 复算哈希 + sympy 公式门 + 撤稿检查） | 伪代码生成 0 竞品 ✅；公式验证业界普遍未做 ◐；AI-Scientist 系被独立复现抓出幻觉引用 ◐ |

### 2.2 不做什么（明确让给生态，避免重复造枝叶）

| 不做 | 交给谁 |
|---|---|
| 通用文献检索工具的重复实现 | 我们只做**入库与自用通路**（arXiv/OpenAlex/Crossref 三个源足够）；广度检索接 `dsh-ai4scholar` / `dsh-paper-search`（能力探测式可选依赖） |
| PDF 整文保版式翻译 | `dsh-pdf-translate`（作为可选增强） |
| OCR / 版面抽取通用件 | 优先 `pdftotext`/`pdfplumber`（✅ 本机已装）+ 可选 `dsh-page-evidence` |
| 通用 GPU 监控看板 | `dsh-remote-gpu-monitoring` 思路；我们只做**作业编排 + 指标归集** |
| 通用定时器与 cron 运行时 | 引擎 `ctx.schedule` / `dsh-cron`；我们只做**科研语义的订阅** |
| Zotero 互操作 | `dsh-zotero*`；我们导出/导入 BibTeX 即可 |
| Slurm/PBS/K8s 适配层 | **本轮不做**，只保留 `ComputeProvider` 抽象（ADR-9） |
| 对话记忆 / RAG | `dsh-kylin-memory` / `dsh-kylin-vibe` |

### 2.3 与 Mimir 的关系

Mimir 是 dsh-only 的九视图大而全（0101 §2.4）。我们**不与之正面重叠**：它的强项（Overleaf 式编辑、arXiv 订阅、SSH 作业）我们做**够用的等价物并接引擎能力**，把资源压在它的三个缺口上（精读产物 / 分级写作 / 真实性链）。两者可以同装（包名、槽位 id、RPC 前缀、storage domain 名全部独立）。

## 5. 双通道契约（R1 的落点）

### 5.1 单包双键（含**回落语义**这一关键事实）

✅ 本会话一手核对（QiLin `packages/util/dsh-compat/src/manifest.ts:22-57`、`packages/util/dsh-compat/src/aliases.ts:20-62`、DSH `packages/client/modules/src/index.ts:791-839`）：

| 事实 | 后果 |
|---|---|
| **QiLin 优先读 `qilin.*`，缺失时回落 `dsh.*`**；DSH **只读 `dsh.*`** | ✅ 只写 `dsh` 键即可双通道通用；**只写 `qilin` 键 → DSH 静默不挂载**（禁止） |
| `bundle.patch` 在 DSH 可为 string **或 string[]**，QiLin 的 `bundlePatchOf` **只认 string** | 一律写**单文件 string**（用 array 形态可能整层被丢） |
| `peerDependencies` 里的引擎包**必须写 `*`**（DSH 侧版本门按 `@deepseek-ai/dsh*` 校验且含 prerelease；写 `^0.2.0` 会被 `0.2.0-rc.2` 拒） | 全部 `*` |
| **`@deepseek-ai/dsh-*` 不得进 `dependencies`**（QiLin 会因 `EngineNameCollisionError` 拒绝整个 profile） | 引擎包只进 `peerDependencies` |
| `client.inject` 里**写错名字在 QiLin 侧是静默忽略**；但服务缺失会激活失败 | 名字清单必须有冒烟断言兜底（§5.2 第 4 条） |

本产品采用**双键内容逐字相同**（同族 `dsh-kylin-automation` / `dsh-kylin-vibe` 的做法，显式优于依赖回落），并由冒烟脚本断言「两键结构一致」。

```jsonc
{
  "name": "dsh-kylin-srw",
  "type": "module",
  "main": "./lib/index.js",
  "exports": { ".": "./lib/index.js", "./client": "./lib/client.js", "./cordis.patch.yml": "./cordis.patch.yml", "./package.json": "./package.json" },
  "files": ["lib", "skills", "cordis.patch.yml", "README.md", "LICENSE"],
  "dsh":   { "bundle": { "patch": "./cordis.patch.yml" }, "client": { "platform": "web", "inject": ["@deepseek-ai/dsh-client-ui-renderer", "…"] } },
  "qilin": { "bundle": { "patch": "./cordis.patch.yml" }, "client": { "platform": "web", "inject": ["@deepseek-ai/dsh-client-ui-renderer", "…"] } },
  "peerDependencies": { "@deepseek-ai/cordis": "*", "@deepseek-ai/dsh-tools": "*", "@deepseek-ai/dsh-llm": "*", "@deepseek-ai/dsh-host-webserver": "*", "…": "*" }
}
```

（`client.inject` 的**精确名单**由 Phase 0 E2 定稿：它是「需要被加载/注入的客户端 bundle 名字」，与 `src/client/index.tsx` 里 `export const inject` 的**服务名**（`slots`/`connection`/`locale`/…）是两回事，别混。）

### 5.2 五条硬纪律

1. **零 `@deepseek-ai/*` 运行时导入**（✅ `dsh-kylin-automation/src/executor.ts` 顶部注释 + `scripts/smoke-plugin.mjs` 第 3 项断言）：打包运行时不向插件提供框架模块，框架包只能 `import type`。需要框架行为时**内联重放**并注明对应版本。引擎包**不得进 `dependencies`**（QiLin 拒绝整 profile），只进 `peerDependencies` 且值为 `*`。
2. **client bundle 必须自注册**：`window.__ModuleLoader__.load({ id, factory: (require) => {…} })`，id == 包名；`react`/`react-dom` external。
3. **浏览器侧只有 9 个可 `require` 的模块**（✅ 一手核对 QiLin `packages/client/web/src/seed.ts:29-38` + `packages/util/dsh-compat/src/aliases.ts:20-28`）：`react`、`react/jsx-runtime`、`react-dom`、`react-dom/client`、`@deepseek-ai/cordis`、`@deepseek-ai/dsh-client-store`、`-ui-slots`、`-ui-primitives`、`-ui-dockkit`。**其余宿主面一律经 `ctx.*` 服务或 `import type` 使用**；源码里**写 DSH 期名字**（麒麟用别名表映射到 `@qilin/*`），写 `@qilin/*` 值导入在 DSH 上直接编译失败。
4. **RPC 首选 `ctx.connection.rpc.handle(channel, handler)`**（✅ `packages/client/connection/src/rpc.ts:156-172`）：栅栏（回环/`trustedHosts`、`sec-fetch-site`、Origin==Host 校验）、浏览器鉴权、**300 MiB body 上限**、结构化 `{ok,value}|{ok:false,error}` 全部自带。裸 `ctx.webServer.register` 是**退路**：它是纯 node:http 路由，**无 body 上限、无路由超时**，栅栏要自己调 `connection.requestRejection(req)`（✅ `dsh-kylin-vibe/src/rpc.ts:80-140`、`dsh-kylin-memory/src/rpc.ts:120-154`）。第三方 patch row 可能拿不到这两个服务 → 用 `ctx.inject(['webServer','connection'], scoped => …)` 动态挂。
5. **对外提供服务必须 `ctx.reflect.provide(name, service)`（或 `extends Service`）**：直接给 `ctx` 赋值属性会抛 "cannot set property without provide"（✅ `dsh-kylin-vibe/src/index.ts:222-224`）。没有这一层，别的插件（包括我们未来拆出的子包）无法 `inject` 我们的能力——**`dsh-kylin-automation` 就是反例**（见 §10.3）。

## 6. 领域模型与数据布局

### 6.1 两级工作区模型（ADR-4）

- **科研总根**（Research Root）：**恰好一个引擎 workspace**，用户用引擎原生目录选择器指定（✅ `directoryPickerController` 见 0101 §5.1）。
- **研究项目**（Project）：总根下的一个子目录 `<root>/<slug>/`，元数据落在项目内 `.srw/project.json`。
- **为什么不是「每项目一个 workspace」**：① 引擎侧栏每加一个项目就多一个 workspace，切项目=切工作区会把「同一份科研上下文」撕成碎片；② 总根下才可能做跨项目的文献库共享与批量操作；③ 引擎已有 workspace 概念，我们**不引入第二套身份**。

### 6.2 磁盘布局（真相源）

```
<root>/                                   ← 引擎 workspace（可被 agent 直接读写）
  .srw/root.json                          ← 总根配置：schemaVersion / 默认刊物 / 默认语言对 / 限速策略
  <project>/
    .srw/
      project.json                        ← 标题/领域/阶段/时间线/目标刊物/深度档
      venue.json                          ← 刊物要求实例（见 §7.3）
      outline.json                        ← 大纲（一级真相源，章节树 + 状态 + 目标字数）
      state.json                          ← 派生索引缓存（可删可重建）
    literature/
      library.json                        ← 文献条目索引（含 source/DOI/arXiv/OA/状态/标签/评分）
      pdf/<citekey>.pdf                   ← 原始 PDF（本地留存，永不分发）
      notes/<citekey>.md                  ← 阅读笔记
      readings/<citekey>/
        paper.md                          ← 段落对齐双语 Markdown（人可读）
        source_map.json                   ← 块 ID → 页码/次序/源文哈希（机可校验）
        glossary.json                     ← 术语表（含出现位置）
        cache/translation.json            ← 增量重译缓存（键 = 块源文哈希）
        meta.json                         ← 进度/模型/语言对/校验时间
    paper/
      main.tex  refs.bib  sections/  figs/  build/
      snapshots/<ts>/                     ← 编译成功留档（tex+bib+pdf+日志）
    experiments/<exp-id>/
      spec.json                           ← 实验设计（假设/变量/指标/数据/基线/停止条件）
      runs/<run-id>/{run.json,stdout.log,metrics.json,artifacts.json,code/}
    materials/
      figures|tables|pseudocode|formulas/  ← LaTeX 源
      manifest.json                       ← 证明链（见 §7.2）
```

### 6.3 为什么「文件是真相源」（ADR-3）

0101 §2.5 的教训与同族产品的实际形态都指向同一结论：**面板一套注册表 + 引擎一套注册表 = 必然漂移**（`ksrw` 前身就吃过大亏：面板读自己的表，引擎工作区是另一套，切项目后读到别的论文）。因此：

- **项目/文献/大纲/精读/素材/实验**：全部以文件为真相源 → 可 git 化、可迁移、可离线、**agent 无面板也能维护**（这是「全流程」能被 agent 驱动的前提）。
- **`storageDomain` 只存**：跨项目索引缓存、订阅定义与运行历史、作业队列、用户偏好。**任何可由文件重建的数据都不进 storage**。
- **域 schema 的硬规则（✅ 一手核对 `packages/storage/storage/src/backend.ts:30-43`）**：**没有迁移机制**——存盘版本 ≠ 声明版本就 `version-mismatch` 拒绝整个 unit（不损坏原文件，但功能整体不可用）。因此：
  - 默认 `layout:'single'`（我们全部先用它）→ **version 一旦发布永不变**，只能「加可选字段 + `.default()`」；
  - 若将来确需改结构，改 `layout:'per-record'` + `compatibleVersions`（旧记录**不会被迁移**，只被接受或按 `invalidRecords:'backup-and-skip'` 备走跳过）；
  - 无事务，**每域一条串行写链**（写序：先落盘 → 再改内存 → 再 emit `domain/changed`）；读出的记录是冻结对象，不得原地修改；`update(key, fn)` 是原子读改写；
  - 落盘位置由宿主决定（`~/.qilin/storages/<unit>.json` 或 `~/.dsh/storages/…`）→ **一律经 `src/host.ts` 解析 home，不硬编码路径**。
- **冲突策略**：文件有 `updatedAt` + 可选 `revision`；写前比对 mtime 与内容哈希，不一致 → 返回 `STALE`（自定义错误码），不静默覆盖。

## 7. 三把尖刀的机制设计

### 7.1 精读产物（R6 / 尖刀 1）

**目标**：产出**可 diff、可迁移、可校验**的阅读产物；译文永远绑定在真实源段上（结构性防幻觉，而非提示词祈祷——0101 §4.4 NotebookLM 复现研究的教训 ◐）。

#### 7.1.1 块模型与稳定 ID

```
块 ID：  p{page}-b{index}          例：p3-b2（第 3 页第 2 个块）
块类型：  title | abstract | heading | para | list | caption | table | formula | reference | code | footnote
源哈希：  srcHash = sha256(normalize(srcText))     normalize = 折叠空白 + 统一连字符 + NFKC
```

`source_map.json`：

```jsonc
{
  "schemaVersion": 1,
  "paperKey": "vaswani2017-attention",
  "source": { "pdf": "literature/pdf/vaswani2017-attention.pdf", "sha256": "…", "pages": 15 },
  "extractor": { "name": "pdftotext", "version": "…", "argv": ["-layout"], "ranAt": "…" },
  "blocks": [
    { "id": "p3-b2", "kind": "para", "order": 42, "page": 3, "srcHash": "…", "chars": 812,
      "quality": "ok",              // ok | suspicious（跨栏断裂/公式混入）| degraded
      "translation": { "target": "zh", "model": "deeps…", "at": "…", "cacheKey": "…" } }
  ]
}
```

**为什么块 ID 要稳定**：笔记、术语出现位置、批注、增量翻译全部挂在块 ID 上；换一次切分算法不能把用户笔记弄丢 → `source_map` 里保留 `extractor` 指纹，切分版本变化时走**块迁移**（按 `srcHash` 匹配旧块 + 新块，能救回多少救多少，救不回的标记 `orphan` 而不是丢弃）。

#### 7.1.2 抽取链（✅ 本机工具链实测 + 宿主能力面核对）

**关键前提（✅ 一手核对）**：**宿主没有主机侧 PDF 文本抽取能力**——`pdfjs-dist` 只装在浏览器包 `ui-sidebar-documentpreview`（`package.json:88`），主机侧只有「MIME 表 + 字节服务」（`host/preview-media`）与反方向的 `office-to-pdf`；生态里的抽取类插件（`dsh-page-evidence` / `dsh-doc-router` / `dsh-kb-rag` …）本机**全部未安装**。→ **抽取器必须自带依赖，不能指望装载现成件。**

| 环节 | 首选 | 备选 | 备注 |
|---|---|---|---|
| 文本 + **坐标** | **`pdfjs-dist` legacy Node build**（自带依赖，`getTextContent()` 给每 item 的 `transform[4]`/`[5]`（x/y）/`width`/`height` + 页码） | `pdftotext -layout`（✅ 本机有；纯文本快但无坐标） | 坐标是**分栏判定与 bbox 锚定**的前提，故选 pdfjs 为默认 |
| 分栏识别 | 全页 item 的 x 中心 1D 聚类/直方图：出现「两簇 + 中间显著空带（gutter）」判双栏 → **先按栏分块，栏内再按 `(y desc, x asc)` 排序** | 单栏则全页按 y 分桶 | ⚠ **绝不能全页按 y 排序**——双栏会左右交错（D-§7） |
| 行重建 | 按 y 容差（≈0.5×height）分桶，桶内按 x 升序拼接、按 x 间距阈值补空格 | — | 这一层决定段落合并质量 |
| 页级元数据 | `pdfjs-dist` | `pdfinfo`（✅） | 页数/标题/作者 |
| 扫描件 | `tesseract`（✅ 本机有） | 远端 OCR | 无文本层时**提示用户**，不静默产出空精读 |
| 结构判定 | 启发式（字号/缩进/编号/关键词） | `ctx.llm` 复核可疑块 | 只把 `suspicious` 块送模型（成本可控） |

**公式与表格的纪律（诚实优先）**：glyph run **重建不出语义 LaTeX**（上下标/分式/矩阵全部退化成线性字符流）。因此：
1. **不从 PDF 反推公式**；优先取 **arXiv 源码**（e-print / ar5iv HTML）里的 LaTeX 原文；
2. 取不到时，公式区域按 viewport **渲染成图片裁剪**，与文本块以占位符关联（`kind:'formula'` + `imageRef`），并**明确标注「公式为图像、非可编辑源」**；
3. 表格同理：检测 ruling line，失败则图片化。

**降级阶梯**（必须显式告知用户当前处于哪一级）：`段级（带 bbox，最优）→ 页级（仅页码锚）→ 无锚（纯译文，禁用于引用）`。

#### 7.1.3 翻译链：分块 + 并发 + 按哈希缓存

- 分块：按块翻译，块内 ≤ 4000 字符；超长段按句切子块；
- 并发：默认 3（可配 1–6），逐块超时 + 指数退避 + 失败重试 2 次；
- 缓存键 = `sha256(targetLang + modelId + srcHash + glossaryHash)` → 改术语表会**定向失效**受影响块（不是全量重翻）；
- 增量：源文重抽后只有 `srcHash` 变化的块进入待译队列；面板显示「变化 N / 复用 M」；
- 成本门：开工前给出「块数 × 平均 token」预估，超过用户设定预算需确认（沿 0101 §6 的成本意识）。
- **语言对**：默认 `en → zh`；支持 `zh → en`、`any → zh`；术语表命中强制使用指定译名（术语表是**硬约束**，不是提示）。

**宿主给不了的（✅ 一手核对，必须自建）**：只有 `ctx.llm.stream`（**没有 `complete`**，用 `BlockAssembler` 收块、从 `usage` chunk 取 token）；`GenerateOptions` **没有 timeout 字段** → 超时用 `@qilin/timeout` 的 `deadline(signal, ms, code)` 融合、`timeoutOf()` 区分「我方超时」与「上游取消」；宿主**没有** `p-limit`/`p-map`/`p-retry`/`p-queue`（全仓零命中）→ **并发闸与重试退避自己写**（`llm-retry` 是 agent loop 专属，不可复用）；宿主也没有 hash 工具 → `node:crypto` 的 `createHash('sha256')`。

#### 7.1.4 渲染与校验

- `paper.md`：每块先源文后译文（译文加 `> ` 引用块或折叠标记），块 ID 以 HTML 注释锚 `<!-- p3-b2 -->` 保留——**人可读、机器可定位**；
- 视图内：左原文右译文（窄屏上下），块高亮联动，术语 hover，`仅原文/双语/仅译文` 三态切换；
- **校验门** `reading.verify`：逐块重算 `sha256(normalize(md 中的源文))` 与 `source_map.srcHash` 比对 → 任一不符即 `mismatch`，UI 红标并**禁止**该产物进入正文引用（这是「译文绑真源」的强制点）；
- 导出：`精读.md`（合并）、`双语.pdf`（后期；用 LaTeX 通道排印，天然复用 §5 的编译链）。

### 7.2 真实性证明链（R7 / 尖刀 2）

**红线（ADR-6，本轮按「全部同意」落为默认值）**：
1. **默认禁止示意（illustrative）实验数据**；正文里的每个数字必须指回真实 `metrics.json` 条目；
2. 若用户**显式**开启 `allowIllustrative`（项目级 + 逐素材确认），则该素材强制**三处标注**：素材水印、论文内脚注、面板红标；
3. 公式 → 强制过 sympy 验证门（本机 **sympy 未装** ✅ 实测 → 门在缺依赖时状态是 `unverifiable`，**不是** `pass`）；
4. 引用 → 入库前查 DOI/arXiv 真伪 + Crossref RetractWatch 撤稿/关切（0101 §4.3）。

`materials/manifest.json`：

```jsonc
{
  "schemaVersion": 1,
  "artifacts": [
    {
      "id": "fig-arch-01",
      "kind": "figure",                     // figure | table | pseudocode | formula
      "path": "materials/figures/arch01.tex",
      "provenance": "derived",              // measured | derived | literature | illustrative
      "generator": { "script": "materials/gen/arch01.tex", "sha256": "…", "ranAt": "…", "host": "local" },
      "inputs": [ { "path": "experiments/exp-01/runs/r3/metrics.json", "sha256": "…", "kind": "measured" } ],
      "output": { "sha256": "…", "bytes": 8123 },
      "verification": { "status": "verified", "method": "recompute", "checkedAt": "…", "detail": "输出哈希一致" },
      "insertedAt": [ { "file": "paper/sections/method.tex", "label": "fig:arch", "line": 88 } ]
    }
  ]
}
```

**四级状态**（UI 与论文里都用同一套）：`verified`（复算一致）/ `mismatch`（复算不一致，**阻断插入**）/ `unverifiable`（缺依赖或缺源，允许插入但强制脚注）/ `illustrative`（示意，强制三处标注）。

**三个门**：

| 门 | 触发点 | 判定 | 不过的后果 |
|---|---|---|---|
| G-M1 溯源门 | 任何素材插入正文 | `provenance != illustrative` 且 `inputs[].sha256` 全部可解析 | 阻断插入，UI 提示缺哪个源 |
| G-M2 公式门 | 生成/插入公式 | sympy 数值或符号等价性检查通过 | 状态 `unverifiable` + 论文脚注「未验证」 |
| G-M3 引用门 | 文献入库 / 生成 BibTeX | DOI 或 arXiv id 可解析 + 未命中撤稿库 | 入库成功但标 `unresolved`/`retracted`；引用它时**阻断** |

**复算**：`verify.recompute(id, {gpuHost?})` → 重跑生成脚本（固定随机种子）→ 哈希比对 → 更新状态。跨主机复算用于「本地画图 vs 远端真实指标」的对账。

### 7.3 刊物要求 schema 与深度档位（R5 / 尖刀 3）

**两层必须分开**（0101 §2.4 的读法）：**格式层**（模板/篇幅/章节/声明/文献样式）与**质量层**（新颖性/去 AI 味/引用审计/投稿清单——已有 4 个生态技能可编排，不重写）。

`venue.json`（项目内实例；注册表随插件分发）：

```jsonc
{
  "schemaVersion": 1,
  "id": "ieee-journal",
  "name": "IEEE Transactions（通用期刊模板）",
  "class": "IEEEtran", "classOptions": ["journal"], "bibStyle": "IEEEtran",
  "columns": 2,
  "pageLimit": { "regular": 12, "note": "模板通用值，具体刊可能不同" },
  "abstractWords": 250,
  "sectionOrder": ["Introduction", "Related Work", "Method", "Experiments", "Results", "Discussion", "Conclusion"],
  "mandatorySections": ["Introduction", "Method", "Experiments", "Conclusion"],
  "mandatoryStatements": ["dataAvailability"],
  "referenceStyle": "ieee",
  "figureDpi": 300,
  "depthTier": "D3",
  "confidence": "unverified",       // ⚠ 关键：外部事实必须人工核定后才参与阻断
  "sources": [ { "url": "…", "checkedAt": "…" } ]
}
```

**深度档位**（本产品自建的产品模型；刊物 schema 通过 `depthTier` 或覆盖字段选用）：

| 维度 | **D1 快报 / Workshop** | **D2 会议全文** | **D3 期刊长文** |
|---|---|---|---|
| 篇幅 | 4–6 页 | 8–10 页（含参考文献） | 12–20 页 |
| 章节 | 略 Related Work 可接受 | 全章节 | 全章节 + 附录（证明/超参） |
| 实验 | 1 数据集 × 2 基线 | 2–3 数据集 × 4–6 基线 + 消融 | 3+ 数据集 × 6+ 基线 × 多随机种子 + 显著性检验 + 成本分析 |
| 图表 | 2–3 图 / 1 表 | 5–8 图 / 3–5 表 | 8–15 图 / 5–10 表 |
| 参考文献 | 20–30 | 40–60 | 60–120 |
| 必备声明 | — | 数据/代码可得性、局限性 | + 利益冲突、伦理、作者贡献（CRediT） |
| 复现材料 | 脚本 | 脚本 + 种子 + 环境 | + 容器/镜像 + 硬件清单 + 统计检验脚本 |

**深度档位的三个落点**（否则只是文档里的表格）：① **大纲生成**按档位产出章节骨架与目标字数；② **实验设计**按档位给出「最少要跑几个数据集/基线/种子」的检查项；③ **合规检查**把上表变成机读 `checks[]`，`srw.paper.compliance` 返回 `{id, level, pass, actual, expected, where}`，UI 可点跳转整改。

**诚实性约束**（防「AI 编造期刊要求」）：注册表里的刊物事实一律带 `confidence` 与 `sources`；`unverified` 只做**建议**（不阻断），用户在投稿视图一次性核定后才升级为阻断。刊物事实的采集必须留 URL 与核对日期。

## 10. 定时抓取与无人值守（R3）

### 10.1 先纠正一件事：`ctx.schedule` 不是任务派发器

✅ 逐行核对（`QiLin/packages/schedule/schedule/src/{index,runtime,storage}.ts`）：

- `create(sessionId, request, signal?)` —— **第一个参数就是 `sessionId`，是必填外键**；实现是 `resolveAgent(task.sessionId)`（**恢复既有会话的 agent**）→ 构造 `source:{kind:'schedule'}` 的 user 消息 → `agent.followup(message)`（追加一轮并**唤醒 driver**）→ `sessions.flush`。文件头注释自陈：*"Session activation is a delivery operation"*。
- 语义细节：**恰好一个** selector（`at`/`after_seconds`/`every_seconds`/`daily`/`weekly`/`cron`）；`every ≥ 60s`；`title` 必填 ≤120；每条规则显式存 IANA 时区；**不补发**（只派发最近一次到期，历史不回放）；一次性投递后转 `inactive`；**对不存在的 sessionId 也会落库**，投递失败只 warn、任务永久卡 `active` 且不自动重试。

→ **结论**：它是「往一个已有会话里定点投消息」的提醒通道，**不能**新建根 agent。**真正的无人值守派发是 `ctx.agents.create(...)` + `agent.followup(...)`**（生产先例：`dsh-kylin-automation/src/executor.ts`、`QiLin/packages/webhook/webhook/src/session.ts`）。

### 10.2 两条车道，职责分开（ADR-8，修订版）

| 车道 | 谁执行 | 用于 | 为什么 |
|---|---|---|---|
| **A 确定性抓取** | **Host 代码**（无 agent、无 token 成本） | arXiv/OpenAlex/Crossref 轮询 → 去重 → 入库 → 通知/摘要 | 例行公事不该烧 LLM；失败可精确重试；离线可审计；**不需要任何 agent 机制** |
| **A′ 提醒投递**（可选） | `ctx.schedule` | 「周一 9 点把本周新增推给这个会话」 | 这正是 `ctx.schedule` 的设计用途（投递到既有会话） |
| **B 无人值守研究任务** | **全新根 agent 运行** | 「本周新论文综述」「按新文献修订 Related Work」 | 需要判断力与写作，属 agent 活 |

**A 车道的时钟**：自建轻量 tick，复用 ✅ `dsh-kylin-automation` 已验证的 `planTick` 语义（**at-most-once**：停机后只补跑**最近一个**到期 occurrence，且只在 `misfireGraceMinutes` 窗口内；更早的推进游标不补跑）——与 `ctx.schedule` 的「不补发」语义天然一致，故不依赖它（`dsh-experimental-schedule-bundle` 且属实验性）。

**B 车道的完整契约**（照抄生产范式，任何一步缺失都会静默出问题）：

```
handle = await ctx.agents.withoutInitiator(() => ctx.agents.create({
  sessionId, meta: { cwd, agentPreset }, agentOptions: { provider, model },
  setup: async (agentCtx, agent) => {
    await ctx.agentPresets.mount(agentCtx, agentPreset)
    agent.session.append('sandbox/mode', { mode: permission })      // ① 沙箱模式
    agent.session.append('approval/policy', { policy: 'never' })    // ② 失败关闭：无人值守不能弹审批
    agentCtx.tools.guard(exec => unattendedToolGuardReason(exec))   // ③ 工具允许清单终审（guard 不能 force-allow）
  },
}))
await handle.agent.whenIdle(); await workspace.attachSession(sessionId)
handle.agent.followup(selfContainedPrompt)          // 提示词必须自包含（不继承任何对话历史）
await Promise.race([handle.agent.whenIdle(), deadline(runTimeoutMs), cancellation])
await ctx.sessions.flush(handle.agent.session)      // 失败路径：detachSession + handle.dispose() 回滚
```

**与 `dsh-kylin-automation` 的关系**：**互操作，不依赖**。✅ 复核确认它的 `AutomationService` 是普通 class（`private constructor` + 静态 `open`），**没有 `extends Service`、没有 `provide`** → 第三方 `inject` 不到；它对外只有 RPC channel、`automation_*` 工具、能力公告段与自己的 storage domain。我们**反向学到的纪律**：**自研服务必须 `ctx.reflect.provide(name, service)`**（直接给 `ctx` 赋值属性会抛 "cannot set property without provide"），否则未来无法被别的插件注入。

### 10.3 礼貌与限速（宿主没有现成件，自建）

0101 §4.3 实测 + 本轮核对：arXiv **1 请求 / 3 秒、单连接**（✅ 硬约束）；Crossref 带 `mailto` 进礼貌池；**Semantic Scholar 匿名池实测 429**（✅）→ 只作 best-effort 二级源 + 退避；OpenAlex 主元数据源。

- 统一 `RateGate`：按域名的令牌桶 + 抖动 + 429/503 退避 + 尊重 `Retry-After` + 上限熔断；
- **跨进程唯一性**用 `withFileLock`（✅ `util/atomic-write:235`），账本（`lastRequestAt` / `seenIds`）落工作区文件 —— 与 ssh-remote 的「文件即事实源 + tmp+rename」同款；
- 单请求超时 `deadline()`；长流无输出用 `idleWatchdog`（✅ `packages/util/timeout`）；
- 宿主确认**无** `p-limit`/`p-retry`/`p-queue`（全仓零命中）→ 并发闸自建。

### 10.4 去重与幂等

条目身份 = DOI → arXiv id → `(title 归一化 + 年份)` 三级 fallback；订阅游标持久化，重复 tick 不重复入库；每条入库写 `firstSeenAt` 与 `seenIn[]`（哪些订阅命中的）。入 `library.json` 并标 `unread`；`overview` 显示「新增 N 条」；**可选**触发 B 车道生成摘要。

| **多主机 + 凭据 + ControlMaster 的事实标准是 `dsh-ssh-remote` 的 `<home>/ssh-remote/hosts.json`**（0644，含内网 IP/端口/用户名，**不含密码**）；密码在独立的 AES-256-GCM 库（`credentials.enc` + 自管 `credentials.key`，均 0600） | `dsh-ssh-remote/lib/hosts.js:35-48,119-128`、`lib/credentials.js:11-64` | 主机列表**可程序化读**；凭据**不该由我们解密** |
| **该插件不暴露任何 ctx 服务**（`apply` 只能返回函数；内件挂在 disposer 属性上） | `dsh-ssh-remote/lib/index.js:736-744` | 复用只能走三条路：读文件 / 只回环 HTTP `GET /ssh-remote/api/hosts` / `ctx.tools.execute('ssh_run', …)` |
| `worlds.json` 里的 helper 是 **`@deepseek-ai/dsh-ssh` 的 PTC helper**（远端 node + helper + `helperHash` + `workspace`） | `~/.kcoder/ssh-remote/worlds.json`（实测） | 与 ssh-remote 的 ControlMaster 是**两套**远端机制，别混为一谈 |

**结论（ADR-9 修订版）**：compute 模块定义 `ComputeProvider` 抽象，首选实现采用**三级优先链**，且**永不读取 `credentials.enc`**：

1. **复用既有 ControlMaster socket**（`<home>/ssh-remote/cm/<id>.sock`）：用户此前用过 SSH 工具时 master 在线 → 我们 `ssh -o ControlPath=<该 socket> …` 即可复用连接，**零凭据**。⚠ 跨插件复用未在其代码/文档声明 → **Phase 0 E4 实测**。
2. **经工具表复用**（`ctx.tools.execute({name:'ssh_run', arguments:{hostId, command}, callId, signal})`，✅ `QiLin/packages/core/tools/src/index.ts:1361`）：借用它已验证的连接与认证；代价是**绕过了它自己的审批链**，所以**必须由我们自己的审批门在前**（§8.2 的 `srw_experiment` 提交门）。
3. **直连**（退路）：用户在 SRW 设置页配置 SSH 私钥路径 / 或重新录入一次 —— 与 ssh-remote 各管各的认证，明确告知用户「这是第二份配置」。

**hostId 陷阱（实测）**：`26训练` 的 id 是 **`30`**（与名字不一致）→ 一律按 **id** 引用，绝不按名字猜。

**必须自建（宿主与生态都为空）**：GPU 盘点（解析 `nvidia-smi --query-gpu=index,name,memory.used,memory.total,utilization.gpu --format=csv`）、**选卡策略 + 每作业 `CUDA_VISIBLE_DEVICES` 注入**、作业队列/去重/重试、指标归集（宿主全仓 `slurm|sbatch|squeue` 零命中，`CUDA_VISIBLE_DEVICES` 仅两处无关命中）。

### 11.2 作业模型与生命周期

`spec.json`（实验设计，**先审后跑**）：

```jsonc
{
  "id": "exp-01", "title": "…", "hypothesis": "…",
  "variables": { "independent": [], "dependent": [], "controlled": [] },
  "datasets": [], "baselines": [], "metrics": ["acc", "flops"],
  "seeds": [0,1,2], "stopCondition": "…", "tier": "D3",
  "compute": { "hostId": "30", "gpus": 1, "cudaVisibleDevices": "auto", "maxHours": 8 },
  "outputs": { "metrics": "metrics.json", "artifacts": ["ckpt/*.pt", "figs/*.pdf"] }
}
```

`run.json` 生命周期（沿 0101 §2.3 的 Mimir 契约，✅ 认同其三个「未观测到结果」终态）：

```
queued → running → succeeded | failed
                 ↘ cancelled | interrupted | unknown      （断线/超时不等于失败）
```

**派发纪律（架构级，不是实现细节）**：远端进程必须**脱离 SSH 会话托管**——远端放 `launch.sh`（选卡 → 设 env → `setsid nohup … > run.log 2>&1 & echo $! > run.pid`），本地只做**短轮询**：

- 为什么：`ctx.ssh` 租约丢失即触发远端托管清理（`leaseMs` 默认仅 30 s ✅）；`ssh_run`/`subprocess` 的句柄生命周期绑在会话上；ssh-remote 的 `ssh_run` 超时**只杀本地进程、远端不保证被杀**（✅ `lib/exec.js:82-86`）→ 挂在调用栈上的长任务会「本地报超时、远端还在跑或已被清理」，两端状态都不确定。
- 观测：`kill -0 $(cat run.pid)` 判存活；日志**按字节偏移续读**（`tail -c +N`，注意 N 是 1-based）；`nvidia-smi` 抽样；退出码写 `exit.code` 文件。
- 本地编排与进度：`ctx.jobs`（`start/list/get/read/readAt/kill/wait/remove`，✅ 双通道逐字同）；日志溢出走远端 spill 或本地 `ctx.spillStore`。
- 采集：`metrics.json` 由约定路径取回；产物按 glob 回传并**逐一记 sha256** 进 `artifacts.json`。
- **上限与显式失败**：单次墙钟上限（默认 8h）、单次捕获上限（默认 4 MiB，超出**显式 failed 并附原因**，不静默截断）；无进展用 `idleWatchdog` 判定（✅ `packages/util/timeout`）。
- 取消：面板取消 / 宿主 dispose / 超时三条路径**合并**为一个 cancel，且**远端 kill 用 pid 文件**（不依赖连接存活）。
- 断线恢复：重连后按 `run.pid` + 日志 mtime 判活；无法判定 → **`unknown` + 提示人工确认，绝不假装成功**。

### 11.3 「按论文设计实验」的闭环

`venue.depthTier` → 实验设计检查项（要几个数据集/基线/种子）→ agent 产出 `spec.json` → **用户确认门** → 派发 → 指标归集 → `materials` 用它生成表与曲线（**带 artifact 指针**）→ `writer` 插入正文 → `投稿` 视图核对「实验完备度」。**这条链是 R7 与 R8 的交点，也是「实事求是」能落地的地方**。

**双通道注意**：DSH 的 `ctx.fs` **没有 `writeBytes`/`createDirectory`/`remove`/`move`**（抽象方法止于 `editText` ✅ `DSH/packages/fs/fs/src/index.ts:305`）→ 二进制落盘（PDF 缓存、产物回传）**统一走 `node:fs` + tmp→rename 原子替换**，不要依赖 `ctx.fs.writeBytes`；需要经引擎时只在麒麟侧启用该分支。

## 12. 安全与合规

**首要事实（✅ 一手核对，改变了「谁来守」的判断）**：**宿主对第三方插件没有任何插件级能力沙箱**——插件代码与宿主**同进程**、拥有完整 Node 权限；`sandbox` 的三种模式（`read-only`/`workspace-write`/`danger-full-access`）只约束**工具调用**（按 session 的 cwd 划界），**没有 egress/网络维度**；插件清单里也**没有** `permissions` 字段。→ 路径逃逸 / SSRF / 凭据三件事**只能我们自己在设计里守**。

| 面 | 风险 | 对策（含正确 API） |
|---|---|---|
| RPC | 任意页面打本地端口 | **首选 `ctx.connection.rpc.handle(channel, handler)`**：栅栏（loopback/`trustedHosts` + `sec-fetch-site` + Origin==Host）、浏览器鉴权、300 MiB body 上限**全自动**；退路（裸 `webServer.register`）必须自己调 `connection.requestRejection(req)` + 自设 1 MiB 上限 + 端点白名单 + 参数校验 |
| 路径 | 逃逸出总根（`../`、符号链接、`~`、绝对路径注入） | ✅ **`resolveWorkspacePath` 不是安全边界**（实测是纯字符串拼接，绝对路径原样返回）。正确姿势：`ctx.fs.resolve(rel, {cwd})` → **`ctx.fs.contains(rootTarget, target)`**（canonical containment）→ 才允许读写；对 `.srw` 另加文件名白名单；`ctx.sandboxPolicy.resolve().workspaceRoot` 取界 |
| 出网 | SSRF（用户/agent 指定任意 URL） | 宿主有正确实现但**不在 package exports** → **照抄策略自实现**：`parseFetchUrl`（仅 http/https、拒 URL 内凭据、长度 ≤2048）→ `resolvePublicAddresses`（解析一次，**任一地址非公网即整组拒绝**，含 NAT64）→ `createPinnedLookup`（把连接钉在已校验 IP，防 TOCTOU 重绑定）→ **拒绝跨源重定向**；再叠加我们的域名白名单（arXiv/OpenAlex/Crossref/S2/bioRxiv） |
| 二进制下载 | `ctx.web` 结构上不支持 | ✅ `WebFetchBody` 是**封闭联合** `{html\|text}`（注释明写不是插件扩展点），`application/pdf` 必抛 `WEB_UNSUPPORTED_CONTENT_TYPE`，且默认 5 MB 上限 → **自建 `globalThis.fetch`**（自动继承宿主已装的 undici 全局代理 dispatcher，无需读 env），自管字节上限 + 流式落盘 + `deadline()` 超时 |
| 限速 | 触发 arXiv/Crossref 封禁 | 宿主**没有** rate limiter/退避调度器 → 自建 `RateGate`（令牌桶 + 抖动 + 429/503 退避 + `Retry-After`）；**跨进程唯一性用 `withFileLock`**（✅ `util/atomic-write:235`，PID 锁 + 退避），账本落工作区文件；单请求超时用 `deadline`，无进展用 `idleWatchdog` |
| 凭据 | 复制第二份密码 / 明文落盘 | **不碰 `credentials.enc`、不解密第三方机密**（§11.1 三级优先链，首选零凭据的 ControlMaster 复用）；SRW 自己的需要（如 S2 API key）走 **`ctx.credentials`**（`resolve`/`describe` 只回 `{configured,source,writable}`、**永不返回值**；落盘 0600 强制校验） |
| 远端执行 | 命令注入 | 远端命令一律 **argv 数组 + 不经 shell**（✅ ssh-remote 与 `subprocess.spawn` 都是这个语义）；需要 shell 语义时显式 `bash -lc` 并把变量作为 argv 传入，**不做字符串拼接**；作业脚本先落远端盘再执行，审计可见 |
| 学术 | 幻觉引用 / 编造数据 / 未标注示意 | G-M1/G-M2/G-M3 三个门（§7.2）+ 撤稿检查 + 「未验证」强制脚注 |
| 法务 | arXiv TOU 禁止代为分发 PDF（✅ 0101 §4.3） | PDF 只落用户本地项目目录；**不**进插件包、不进任何同步/分享通道；导出只导路径与元数据 |
| 数据 | 用户论文/主机信息泄露 | 全部本地文件；**`hosts.json` 只读复用、不复制进工作区、不进日志**（含内网 IP/端口/用户名）；LLM 调用只送必要文本块，并在设置页明示「哪些内容会送到模型」 |

## 13. 失败模式与降级矩阵

| 缺失/失败 | 影响 | 降级行为（必须可见，不许静默） |
|---|---|---|
| 无 TeX 引擎（✅ 本机四个全缺） | 编译不可用 | 进页面即探测；显示安装引导（`brew install tectonic`）；「远程编译」作为后续增强 |
| 无 LaTeX 引擎但有远端主机 | 本地编译失败 | 提供「在 26训练 上编译」（阶段二） |
| 无 LLM provider | 精读/摘要/评分不可用 | 逐项置灰 + 原因；**正文读写与编译、文献入库、素材生成不受影响** |
| 无网 | 抓取失败 | 订阅标 `offline-skip`，恢复后只补最近一次；本地阅读与写作完全可用 |
| SSH 主机不可达（✅ 本次两台均超时） | 实验不可跑 | 主机卡片显示不可达 + 上次成功时间；作业保持 `queued` 不假跑 |
| 无可用 ssh 通路（master 不在线 + 工具表不可用 + 未配私钥） | 实验不可跑 | compute 视图整体禁用并给出「三条通路各自怎么修」的说明（§11.1） |
| 缺 `sympy` | 公式门无法判定 | 状态 `unverifiable`（**不是 pass**）+ 提示安装；可指定远端环境执行 |
| 缺 `pdfjs-dist` 或 Node legacy build 加载失败 | 精读不可用 | 精读视图置灰并给出错误；**已入库 PDF 与笔记不丢**（文件仍在） |
| PDF 无文本层 | 抽取为空 | 提示走 OCR（tesseract 已装）或标记 `degraded`，禁止进入引用 |
| **DSH 侧 `ctx.fs` 缺 `writeBytes`/`createDirectory`/`remove`/`move`**（✅ 实测） | 二进制落盘/建目录/删除 | 统一走 `node:fs` + tmp→rename；`src/host.ts` 暴露 `writeBinary()` 单点适配，调用方不感知 host |
| `ctx.fs.watch` 恒失败（✅ 本地后端不支持） | 文件变更事件 | 自建 `node:fs.watch`（带防抖）或轮询；不要依赖它 |
| `ctx.jobs` 抽象座位未装实现 | 长任务进度不可用 | 退化为插件自有 job 表（文件 + 内存）并如实标注 |
| `ctx.web` 取到非文本响应 | 抓取失败 | 二进制路径本就不走 `ctx.web`（§12）；文本源失败按源退避换源并显示 |
| 生态插件缺席（如 `dsh-page-evidence`，✅ 本机全 ABSENT） | 增强能力缺失 | 能力探测 + 内置最小实现（ADR-1 的依赖策略） |
| 麒麟侧 client 不挂载 | 面板不可用 | 功能降级为「agent 工具 + 技能 + 命令」，RPC 仍可通过对话驱动 |
| `hosts.json` 不存在或格式变化 | 主机列表空 | 显示「未发现已注册主机」+ 引导（去 SSH 插件页添加 / 或在本插件设置页手工添加），**不猜、不伪造** |

### 17.4 宿主能力面速查（本轮四路调研 + 我本人复核的结果汇总）

| 能力 | 结论一句话 | 我们的用法 |
|---|---|---|
| 持久化 | `defineDomain`/`domainTable`/`open` 完备；**无迁移**，version 发布即冻结；无事务、每域串行写链 | 只存索引/缓存/队列（ADR-3）；schema 永远 additive |
| RPC | `connection.rpc.handle` 自带栅栏+鉴权+300 MiB；裸路由无上限无超时 | 首选前者，退路后者（ADR-14） |
| 调度 | `ctx.schedule` = **投递进既有会话**（sessionId 必填），**不补发** | A′ 提醒用；派发用 `agents.create`（ADR-8） |
| agent 派发 | `withoutInitiator(agents.create) + setup(sandbox/approval/guard) + attachSession + followup + whenIdle` | B 车道逐行照抄（§10.2） |
| 工具/技能/命令 | `defineTool`（自有 JSON-schema DSL）+ `output.render`；技能 rank 越低越优先；命令不经模型 | §8.2/§8.3 |
| 审批 | `tools/pre-execute` 返回 `ask{reason,displayReason}`；`tools.guard` 单调、不可 force-allow | 写操作与远端作业门 |
| LLM | 只有 `stream`（无 complete）；无 timeout 字段；**无重试/并发/hash 工具** | `deadline` 超时 + 自建并发闸与重试（§7.1.3） |
| 出网 | `ctx.web` 只出文本（封闭联合）；**自建 fetch 自动继承 undici 全局代理** | 文本走 `ctx.web`，PDF 自建（ADR-16） |
| 文件 | `ctx.fs` 完备（含 `contains`）；**DSH 缺 writeBytes/createDirectory/remove/move**；`watch` 本地不支持 | `node:fs`+rename 单点适配（ADR-20） |
| 远程执行 | `ctx.ssh` = 单主机单租约非注册表；多主机事实标准在 ssh-remote 的 hosts.json（无 ctx 服务） | 三级链（ADR-9） |
| GPU / Slurm | 宿主与生态**全为空** | GPU 盘点/选卡/env 注入自建（§11.1） |
| PDF 抽取 | 宿主**只有浏览器侧** pdfjs；生态抽取器本机全缺 | 自带 `pdfjs-dist` legacy Node（ADR-17） |
| 限速 | 宿主**无限速器**；可用 `deadline`/`idleWatchdog`/`withFileLock` | 自建 `RateGate`（§10.3） |
| 安全 | **插件无能力沙箱**（同进程全权限），清单无 permissions 字段 | 红线自守：`contains`/SSRF 三步/`ctx.credentials`（§12） |
| UI 槽 | `main` keyed 可用；右栏在主区被占时**抛错**；文档预览只在右栏；设置自绘页是 portal 模态 | 主区面板 + 自绘预览 + overlay 侧车（§9） |
